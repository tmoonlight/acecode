# 经典桌面宠物素材

Clippy（43 个动作）与 Rover（29 个动作）原始 PNG 精灵图和动作数据来自 [clippyjs/clippy.js](https://github.com/clippyjs/clippy.js)，固定提交和 SHA-256 见 `sources.json`。`preview.png` 直接裁取原图的 RestPose 首帧，仅用于设置中的预览。

## 高清帧（hd/）

原精灵图只有 124×93（Clippy）/ 80×80（Rover）、256 色抖动，放大到 350 像素以上满是锯齿。2026-10-31 起页面不再使用 `map.png`，改用 `hd/` 里的高清版：Clippy 496×372 逐帧重画，Rover 是 108×108 的像素画、由 Grok 生成的视频抽帧（见下一节；鲸鱼娘 512×512，见 `../whale/README.md`）。`map.png` 与 `agent.js` 保持上游原样：Clippy 的 `map.png` 是重画的参考和对齐基准，`agent.js` 仍提供每个动作的帧序、时长和分支；Rover 的时序改由 `hd/frames.js` 自带的 `agent` 表提供。

重画用 Codex 的内置图像生成（codex-cli 0.166，`image_generation`），脚本在 `scripts/desktop_pet/`，按顺序运行：

1. `hd_make_grids.py`：收集页面会播放的动作（`classic_pet.js` 的 `PROFILES` 加 RestPose；鲸鱼娘全部动作）用到的帧，合并只差抖动噪点的近似重复帧，按播放顺序每 9 帧（鲸鱼娘 4 帧）排成一张参考网格，原帧最近邻放大到 4 / 5 倍、纯绿背景。重跑时保留已有网格，只为新增的帧排新网格。
2. `hd_codex_redraw.py`：8 路并行调用 `codex exec`，每次附两张图：参考网格，以及同一角色的高清定稿图（先单独重画的一张 RestPose，用作风格锚点，保证各次重画的材质、线条一致）。提示要求网格、每格的姿势位置大小颜色都不变。输出纯绿背景抠成透明（按绿色溢出量做软边、去绿边），切格后按原帧轮廓对齐：同一张图共用一个缩放（Codex 在一张图内比例稳定），大格各自微调位置，小目标（只露出眼睛、刚从纸里钻出来等）沿用大格的位置只做小范围微调。大格轮廓重合度低于 0.85 或小格低于 0.45 时重画，最多 3 次；`--reselect` 从已有的各次尝试里重新挑对得最好的一张。
3. `hd_assemble.py`：对齐后的帧缩到发布尺寸（Rover 由 5 倍缩到 4.5 倍），裁掉透明边，按动作的播放顺序打包成每张不超过 2048×2048 的 WebP（质量 75，透明通道无损），写出 `hd/frames.js`：`frames` 以原精灵偏移 `"x,y"` 为键，值为 `[图序号, x, y, 宽, 高, 帧内偏移 x, 帧内偏移 y]`；`animations` 列出每个动作用到的图，也决定哪些动作可播放。页面只解码播放位置往后 16 帧所在的图，超过约 1600 万像素时丢掉最久没用的。`scripts/embed_desktop_pet.py` 按序号嵌入全部图（三只合计约 10.5MB）。

## Rover：像素画 + Grok 视频（rover/hd/）

逐帧重画的 Rover 表情不自然，3D 渲染的视频版用户也不喜欢；2026-10-31 定为 2D 像素风（也为了体积：整套 846KB，3D 视频版 10MB）。脚本在 `scripts/desktop_pet/`：

1. 底图：Codex 按文字（不给参考图，参考原帧时后腿结构会画乱）生成 4 张像素风坐姿，用户选定一张。它的“像素”并不在严格的网格上，`grok_rover_pixel_base.py` 把它抠绿、缩放到狗高 100 像素后在我们自己的网格上重新像素化（`pixelate.py`：每格取多数色、深色描边占三成以上优先、八叉树调色板 32 色，保住红项圈和眼白），放进 720×720 视频画布（每个像素放大成 5×5，108×108 的精灵方框在底部居中，上方留出跳跃空间）。
2. `grok_rover_videos.py`：26 个动作各写一句动作描述（按原动作内容：足球锦旗、厨师锅、报纸、书、钞票、场记板、行李箱、相框等道具），用 Grok Build CLI 的 `reference_to_video`（Grok Imagine，720p、24fps）生成，首帧与尾帧都钉成这张底图，所以每段都从坐姿开始、回到坐姿结束，循环无缝；入场动作 Show 只钉尾帧。提示要求保持像素画风格、道具和角色身上不能有绿色。运行目录用短编号：CLI 按编码后的工作目录建会话文件夹，名字长的动作曾超过 Windows 260 字符而保存失败。
3. `grok_rover_assemble.py`（需要 PyAV）：每段按 12fps 抽帧、按画面边缘取样的底色抠绿，再用同一网格和调色板重新像素化（底图 32 色 + 道具补充 16 色）；与上一帧几乎没变的格子沿用上一帧，视频噪点不会让静止部分闪烁；首帧直接用底图，相同的连续帧合并成一帧加长时长、相同帧只存一份，打包成无损 WebP，写出带 `pixelArt: true` 和 `agent` 时序表（动作名与 `agent.js` 相同）的 `hd/frames.js`。拖动时停在指向姿势的帧号为 10（第 9–24 帧是指向姿势）。

页面对 `pixelArt` 的图先按最近邻放大到整数倍、再平滑缩到实际大小，任意窗口缩放下每个像素都是同样大小的方块；像素宠物不叠加“呼吸”缩放（会让像素行闪动）。

## 趴边偷看（clippy/peek.png、rover/peek.png）

宠物拖到屏幕左/右边缘吸附后改用各自目录下的 `peek.png`：两帧并排（左睁眼、右闭眼），透明背景，画面右缘就是它躲着的那条屏幕边（贴左边时页面水平镜像）。不来自上游项目：2026-10-16 先用 Codex 画出精灵分辨率的版本（回形针把上半截钢丝和两只大眼睛从画面右缘探进来，rover 探出脑袋、两只前爪扒着右缘），2026-10-31 回形针的由 `scripts/desktop_pet/hd_peek.py` 以那一版为参考、以高清定稿图为风格锚点，用 Codex 重画到与高清帧相同的倍数（4 倍）；rover 的是像素画：Codex 以像素底图为设计参考画出从右缘探头的样子（三张挑一张），再做一次“只闭眼”的编辑，`rover_pixel_peek.py` 用同一网格和底图调色板像素化到 76 像素高（65×76 一帧），闭眼帧只取睁眼帧眼白周围的方框，其余像素完全相同。闭眼帧只取两帧原图有差别的眼睛区域（外扩、羽化）贴到睁眼帧上，眨眼时其余像素不动。偷看图与各自的帧同倍数，所以 `classic_pet.js` 的 `PEEK` 表里两者的 `ratio` 都是 1。
