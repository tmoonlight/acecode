## Why

ACECode 专家组件目前只有一张静态主头像，数据模型无法为工作中、需要用户关注或空闲等状态保留不同视觉资产。先建立兼容、可编辑、可持久化的数据契约，能够让后续运行时状态切换在不再次迁移专家包的前提下落地，并允许 GIF 状态头像保留动画。

## What Changes

- 为 Agent 和 Team 专家组件新增可选的状态头像集合，固定支持 `working`、`needs_attention`、`idle` 三种键；manifest 使用 `stateAvatars`，API/前端模型使用 `state_avatars`，值均为专家包内图片的相对路径。
- 保持现有 `avatar` 主头像完全兼容。任一状态头像未配置时，该状态的有效头像回退到主头像；已经通过校验的状态图片若在读取时瞬时不可用，也安全回退主头像。主头像也缺失时继续沿用现有无头像表现。
- 扩展专家读取、DTO、创建/更新和管理编辑器，使三类状态头像能够被配置、清除并无损往返；更新其它专家字段时必须保留未修改的状态头像、图片文件和未知 manifest 扩展。
- 状态头像复用现有安全边界：路径必须留在专家包内、目标必须存在、响应遵守现有头像大小和 MIME 白名单。明确支持 PNG、JPEG、GIF、WebP、BMP 和 ICO；GIF 文件按原始字节保存和返回，不转码、不抽帧，确保未来选中相应状态时可以播放动画。
- 同步 `expert-manager` Skill 的 schema、头像规范和校验脚本，使对话式/脚本化专家创建能够生成并验证同一字段；旧专家包无需迁移即可继续使用。
- 本阶段不根据 Agent、子代理或提问状态自动切换头像，也不新增完整的运行时状态 UI。实现与验证完成后，在 `docs/待办.md` 清单末尾追加一项未完成待办，描述后续按子代理状态选择上述头像。

## Capabilities

### New Capabilities

- `expert-state-avatar-data`: 专家状态头像的 manifest/API/编辑持久化契约、图片安全校验、GIF 原样保留和主头像回退规则。

### Modified Capabilities

无。现有主头像行为保持兼容，运行时动态切换作为后续能力单独规划。

## Impact

- C++：`ExpertDefinition`/`ExpertDraft`、专家包解析与原子更新、专家 HTTP DTO/头像读取和相关单元/HTTP 测试。
- WebUI：专家数据归一化、编辑表单与 payload、状态头像预览/清除所需的安全 URL，以及相关前端测试。
- Seed Skill：`expert-manager` 的 `expert.json`/头像参考规范和 Python 校验流程。
- 数据兼容：现有 `avatar` 字段和无状态头像的旧包保持有效；不重写或转码已有图片资产。
- 文档：仅追加未来运行时动态切换的未完成待办，不把完整动态头像能力误标为已完成。
