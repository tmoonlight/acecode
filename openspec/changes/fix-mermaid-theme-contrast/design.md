## Context

见 proposal.md。现有渲染器仅检查根节点的 data-theme，以 Blob 图片展示经过净化的 SVG。自定义主题可以在深色模式下配置浅色对话背景；现有观察器也不会响应仅改变颜色变量的更新。

## Goals / Non-Goals

目标是让默认线条和文字与实际纯色背景有足够对比，保持图表原尺寸、透明显示及安全渲染边界。用户源码中的显式样式继续生效，本次不改变主题包格式或用户背景图片。

## Decisions

1. 从图表元素向祖先读取浏览器计算后的背景色，并合成半透明纯色层。缺少 DOM 样式信息时才回退到主题标记。比较黑白文字与背景的相对亮度对比度，选取更清晰的一侧，避免单纯使用主题名称或固定亮度阈值。
2. 继续使用 Mermaid 的浅色与深色预设以保留节点填充风格，为五种已支持图表显式配置关键线条、边框和文字色。黑白前景在任意纯色背景上的较高对比值不低于 4.5:1。复用任务栏徽标的对比度算法。
3. 观察主题标记、颜色主题、样式、类名和背景开关变化；只重置受影响且实际明暗配色已改变的图表。全局背景过渡结束或取消后再次检查实际颜色，避免在属性变化时只读到动画起点。异步渲染和图片加载均重新检查实际背景，避免旧图覆盖新配色。
4. 预览与导出继续使用已解析的明暗值及同一 SVG，不增加渲染入口或改变图片尺寸。

## Risks / Trade-offs

- 背景图片、渐变或源码显式颜色可能具有局部颜色差异 → 默认配色以实际纯色底色为依据，不采样私人图片或重写用户样式。
- 观察属性范围扩大 → 忽略图表内部样式变化；批量处理祖先属性变化，仅在解析后的配色改变时重绘，避免渲染循环。
- 静态资源已构建不代表桌面窗口已加载 → 核对桌面守护进程的资源目录和实际 HTTP 页面，区分资源更新与窗口重新加载。

## Migration Plan

运行定向及完整 Web 测试、构建、真实浏览器主题切换与分数 DPI 验证；按已有授权合入主干并更新桌面使用的 Web 资源。回退时还原本次提交并重新构建资源。
