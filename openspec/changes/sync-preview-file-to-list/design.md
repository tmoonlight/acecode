## Context

ChatView 保存定位请求，SidePanel 已能展开、选中与滚动。现有目录定位请求总是 includeSelf，不能直接用于文件。详情通过全局上下文菜单派发事件；快捷键已有统一目录、配置与作用域控制。实际根目录是 sidePanelCwd，预览标签 cwd 可能是外部文件父目录。

## Goals / Non-Goals

统一菜单和快捷键的文件定位入口，在任何界面变化之前校验实际工作区归属。仅修改本功能相关前端和文档，不改其他工作区已有修改，不改变系统文件管理器入口。

## Decisions

1. 文件绝对路径由标签 cwd/path 解析，再与当前实际根目录比较；复用路径规范化约定，处理 Windows 大小写、UNC、点段和相邻前缀。无工作区直接拒绝，不以外部预览 cwd 充当根目录。
2. 新动作由详情面板统一接收并调用 ChatView 文件定位回调；右键使用对应标签/内容的路径，快捷键使用活动文件。菜单事件限定在当前面板，避免跨视图重复执行。沿用统一快捷键仓库，默认 Ctrl+[，编辑器内可用，弹窗和输入法组合期间不执行。
3. 扩展定位请求的文件/目录语义及强调标记；沿用递增 token 支持同路径重复定位。SidePanel 在请求挂载时也必须消费尚未处理的请求，目录加载完成后再滚动和强调。
4. 高亮仅作用于目标行，760ms 内放大到 1.06 倍再恢复，使用现有主题色。缩放图标与文件名，行背景强调，避免改变列表尺寸或横向溢出。减少动态效果取消缩放。下一帧确认列表挂载与可见后滚动并播放，避免 StrictMode 重放挂载提前消耗请求；卸载取消待执行帧并清理旧效果。按请求 token 记录已播放状态，不因缓存更新、普通选中或会话恢复重新播放。
5. 使用真实 App 的隔离浏览器测试覆盖菜单、快捷键、折叠列表、深层懒加载、重复定位、外部文件及减少动态效果；补充路径纯函数与菜单/快捷键测试。

## Risks / Trade-offs

- 列表挂载或加载时丢失请求 → 按 owner/cwd 和 token 消费，只有实际目标可见时记录完成。
- 窄窗口或详情最大化遮住列表 → 使用现有列表展开和响应式右栏入口。
- 外部文件在简单前缀检查中误命中 → 规范化路径后检查完整目录边界。
- 旧 WebView 动画能力 → 使用 CSS keyframes 和主题 token，不引入新依赖。

## Migration Plan

构建 Web 产物即可交付源码；已安装 Desktop 需后续重新嵌入前端并启动后才能宣称桌面运行验证。无数据迁移。
