## Context

参见 proposal.md。上游本机 HEAD 为 `687f282e86`（2026-10-17），工作树干净。ACECode 本次开始时位于干净的 master。当前已有虚拟行、搜索索引和时间线缩放，且已有 ACECode 专用回合身份和 WebView 109 色彩回退。

## Goals / Non-Goals

目标：同步用户可见且可由现有记录支撑的改进，保持现有界面风格与精简文案。

非目标：迁移 DeepSeek 的插件注册、Session V4、PTC 执行引擎或授权图像缓存；增加 ACECode 尚不存在的事件来源；发布或替换已安装 Desktop。

## Decisions

1. 复用上游详情与 JSON 检查组件，替换包级依赖为 ACECode 图标、Markdown、剪贴板和附件适配。避免直接引入整套上游框架。
2. 保留 `trajectoryModel.js` 的稳定 turn_id/user_message_id 归属，以及 `layout.ts` 的 inputTurns 修复。在现有事件投影上修正请求/输出生命周期及重试历史。
3. 采用上游代码检查对工具真实名称和记录时 schema 的判定。记录中存在 run_code 时可查看，但不为 ACECode 添加执行工具，也不把普通工具猜测为代码工具。
4. 保留现有主题和兼容 CSS，在原组件上补充新交互需要的样式；附件采用现有安全图片 URL 和 ACECode 附件接口，不加载任意文件路径。
5. 核对 `9bdd420512`、`37c2fa40ac`、`31ff3a73c0`（生命周期），`18739de7c6`、`3a32c617a3`（JSON），`632b8e19b4`、`b6858789f0`（代码），`1da97f30f8`（附件），`e5038fcf9e`、`039415d5a4`（思考内容）。上游专属消息来源和数据协议只记录适配边界，不引入虚假记录。

## Risks / Trade-offs

- 上游类型与 ACECode 事件格式不同：以 ACECode 的真实事件顺序及模型测试验证，原始内容不靠展示字符串反推。
- UI 移植可能影响跳转与滚动：运行真实组件浏览器回放，覆盖大历史、展开、搜索和流式更新。
- 新 CSS 可能使用新浏览器特性：保留已有回退并扫描新增样式。
- 安装版内嵌前端独立：本次构建和浏览器验证不代表已安装桌面程序已更新。
