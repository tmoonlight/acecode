## Decisions

### D-1 记录归属会话，页签只是端点

```
Session
 ├── SessionAnnotationStore        ← records / in_flight / 按 page_id 分组的 next_number
 └── Page
       └── PageAnnotationSession  ← 选区、预览、document_id；页签关闭即析构
```

**为什么**：只要记录的生命周期短于「输入框上方的待发卡片」，`pages.erase(page_id)` 就会把用户写到一半的描述一起析构。反过来把记录挂在会话上，页签只剩三样会失效的东西：DOM（预览/调整）、`document_id`（重放）、`executionContextId`（下发命令）——正好对应 `orphan` 态。

**代价**：改动面大，`records` 的读写要穿过两层。缓解：先做纯搬运（行为零变化）一次性落地，再加 `orphan`，两批分开评审。

### D-2 四态

| 态 | 可发送 | 画图钉 | 可重放 | 可调整 |
|---|---|---|---|---|
| `live` | 是 | 是 | — | 是 |
| `replayable` | 是（标 `target_invalid`） | 否 | 是 | 否 |
| `stale` | 是（标 `target_invalid`） | 否 | 否 | 否 |
| `orphan` | 是（标 `target_invalid`，图沿用 save 时那张） | 否 | 否 | 否 |

`replayable` 隐藏「调整」的原因：重放还没成功，样式面板读到的是错的 baseline，改出来的 `old_value` 是脏的。

### D-3 消息组装唯一，触发三处

消息只在 composer 组装一次（`submitWithAnnotations()`）。三处调它，效果完全等价：把输入框内容和会话内全部待发批注批量提交。

| 触发点 | 语义 |
|---|---|
| 会话输入框的发送按钮 | 原生入口 |
| 页内工具栏的发送按钮 | 等价于点输入框发送：输入框现有内容 + 会话内全部待发批注 |
| 浮窗 `Ctrl+Enter` | 先 `save` 当前这条，再触发同一个提交 |

**为什么保留工具栏发送**：用户在页面上刚批注完，视线和鼠标都在页面上，让他切回对话再点发送是多余的一步。保留按钮不会带来「发到哪个会话」的歧义——提交动作恒定作用于「页签所属面板的那个会话」。

**为什么组装点只能有一个**：两个触发点各自组装 payload，就会出现「工具栏发一条、输入框又发一条」的双发路径，agent 会分两次读同一批批注、跑两轮 turn。所以工具栏按钮不自己组装、不自己 POST，只调同一个函数。

**约束**：

- 提交范围是**会话全量**（跨页签 + `orphan`），不是当前页签那几条。页内工具栏
  的数字仍只描述当前页签，避免别的页签的条数跑到这页工具栏上；会话总数由输入框
  上方的待发卡片统一展示。
- 输入框里的草稿文本**会一并发出**（用户明确要求「把聊天框里的内容和所有批注批量提交」），不做丢弃分支。
- 回执状态（成功 / 失败 / 40s 自查结果）统一由 composer 的发送状态机广播，工具栏与输入框显示同一状态。

**合并成一条消息**：正文只放用户文本；批注结构作为 `contexts` 里的
`{type:"page_annotations", version:2, pages:[...]}` 提交，服务端转成
`page_annotations_context` content part，并把净化后的来源、元素、描述、网页文本
和样式差异展开进模型正文；原始文本继续作为显示文本。拆成两条 POST 会触发
两轮 turn。消息渲染只认上下文部件，不解析正文内嵌载荷。

**铅笔路径的页签解析**：编辑注册表只属于当前挂载的页签，不能据此判断其它页签
是否还存在。先按 `page_id`、再按 `url` 在 App 级浏览器页面登记表中定位页面；
命中后激活该页签并等待新面板发布带 `document_id` 的编辑器，再执行
`edit_record`。只有登记表和页签都不存在，或原生确认目标已失效时，才进入无页签
弹窗。无页签弹窗的描述始终可编辑，按钮在「编辑」与「保存」间切换，保存后停留
在弹窗内并更新待发卡片。

**页内浮层几何**：批注输入框、调整面板、工具栏和悬停气泡都叠在原生浏览器
视图上。原生遮挡洞用矩形区域，圆角、边框和阴影全部交给 Chromium 绘制；洞口
外扩 1 CSS px，并用当前页面背景色填底，避免 native `CreateRoundRectRgn` 的
非抗锯齿边缘在黑底上露出锯齿。

### D-4 待发卡片

输入框上方，跨页签聚合（原生在任一页签记录变化时广播 `{session_id, page_id, annotations}`，WebUI 按 `session_id → page_id` 归并并单独维护 `orphans[]`）。最多展示 5 行，超出内部滚动。

铅笔两条路径：

- 页签活着：激活页签 → 隐式 `start()`（D8：把页面拉回批注模式）→ `open_record_popup` → 描述回填 + 光标置末尾 + `focus()` + 图钉高亮 + 差异还原成 draft。「调整」可用。
- 页签已关：居中弹窗，只有描述框 + 删除 + 取消/保存；`target` 冻结，locator / region / differences 只读。**「调整」隐藏**——没有 document、没有 baseline，硬留只会点了报错。

`adjustable = state === 'live' && 页签存活 && document_id 匹配`，两个入口共用这一条判定。

删除 = 立即生效 + 单槽撤销 toast，不做二次确认（批注是轻量草稿，弹窗打断比误删更烦）。

### D-5 截图在 save 时裁

```
save → 视口捕获一次（scale = 1/dpr）→ 按目标 rect 裁剪 → 缩到宽 ≤512px → record.thumbnail
发送 → 只上传 thumbnail
```

**为什么**：保存那一刻页面正停在目标上，坐标最准；等到发送时可能已经导航、重放或关掉了。顺带解决「关页签就没图」：图在 save 时就定格，`orphan` 记录仍有图。

**代价**：每次 save 多一次捕获（Windows 一次 CDP 调用）。保存批注是低频动作，换来「发送时零捕获」。`captureBeyondViewport` + `cssContentSize` 的整页路径可以删掉——视口够用，视口外的目标本来也没有坐标能裁。

### D-6 超时自查

```
40s 未收到 WS message
 ├─ 按 client_message_id 查到 → 视为成功，丢弃 in_flight
 └─ 查不到 → 回滚：并回 records 尾部、重排编号、sync、toast
```

`client_message_id` 已经写进消息 `metadata` 落库（`routes_sessions.cpp:524`），WS 回推也带回（`:734-738`）。没有自查的话，一次 WS 抖动就让用户重发，agent 收到两条一样的批注、把同一处改两遍。

**自查本身失败**时按「未知」处理：不回滚，只提示。宁可让用户看到一条"可能已发出"的记录，也不要制造重复。

### D-7 已发消息只读

没有编辑消息的 API，transcript 只追加。卡片不给铅笔、垃圾桶、复制、"回到页面修改"。想做新一轮修改 → 回页面重新批注一条新的（显式、留痕）。

### D-8 按住看原图只认指针

「按住看原图」是**纯指针动作**：`pointerdown` 进、`pointerup`/`pointercancel`/`pointerleave` 出，外加 `blur` 与 `visibilitychange` 两路兜底。**不注册任何键盘快捷键**——空格与 Enter 都不触发。

**为什么砍键盘**：这个动作的语义是「按住不放」，键盘上没有"按住"的对应物（按住空格会触发系统按键重复，`keydown` 连发、`keyup` 只在松开时来一次，但中间的用户感知是"按一下就开始、再按一下才停"，与"按住"不是同一件事）。而且批注面板里已经有三个真快捷键（Enter / Shift+Enter / Ctrl+Enter），再加一个瞬时按键会让"Enter 是添加还是对比"变成需要记忆的事。

**代价**：纯键盘用户用不了对比。接受——对比是视觉辅助，不是完成批注的必要路径；按钮保留 `aria-label`「按住查看原图」说明它是瞬时动作。

**实现注意**：按钮要 `preventDefault` 掉 Enter 的默认激活，否则聚焦后按 Enter 会触发一次 `click`，而 click 对"按住"没有语义。

## Alternatives considered

| 备选 | 否决理由 |
|---|---|
| 记录留在页签，关页签前弹窗问「要丢弃还是保留」 | 打断路径，且用户常在无感知时关页签 |
| 已发消息可就地编辑（新增消息编辑 API） | agent 已按旧描述执行，改历史会让 transcript 与执行结果对不上 |
| 发送时一次整页捕获 + 逐条裁剪 | mac 根本不返回整页；且发送时页面可能已经变化 |
| 待发卡片自己带发送按钮 | 卡片就贴在输入框上方，输入框发送按钮已在手边，再加一个是冗余 |
| 缩略图用 `tag` + 文本片段代替真图 | 用户明确要截图（D2），且 save 时已有捕获时机 |

## Risks

| 风险 | 缓解 |
|---|---|
| 记录上提改动面大 | 纯搬运与 `orphan` 分两批；P1 阶段行为零变化 |
| 跨页签编号重复（每页从 1 开始） | 每条自带 `page_url`，卡片与模型都按页分组；`number` 只在页内唯一 |
| `sync` 频率上升（还要广播所有页签） | 缓存 `executionContextId`；只给有记录变化的页签发事件 |
| `orphan` 记录长期占内存 | 会话关闭即清空；卡片行标「页面已关闭」 |
| 自查接口本身失败 | 不回滚、只提示（见 D-6） |
