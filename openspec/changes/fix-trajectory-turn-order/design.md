## Context

现场只读接口确认事件顺序为 legacy_context、message(user)、turn_start、model_step_start、model_request、model_response、turn_end。当前投影遇上下文创建匿名回合，遇用户消息创建回合，遇 turn_start 强制再建回合。四次输入被投影为 3、5、7、9。

布局原先通过下一个助手或 partial 推断输入归属；尚无助手结果时请求与用户行可落入不同回合。实时 partial 的 turn 则来自聊天计数，与轨迹投影不是同一身份来源。

## Goals / Non-Goals

目标：修复投影身份和实时布局，并兼容用户消息早于或晚于 turn_start 的事件顺序及旧会话。

不改变后端事件协议、磁盘记录、轮询频率、轨迹视觉样式；不把加载局部历史时缺少的绝对回合总数伪装为已知数据。

## Decisions

1. 上下文暂存至真正回合建立，再附入该回合；turn_start 复用 turn_id 或 user_message_id 对应回合，结束事件不创建新回合。保留仅有上下文的历史展示。
2. 投影产生输入序号到回合编号的映射，布局优先使用该映射，兼容未提供映射的 DeepSeek 输入。系统提示使用所属请求的回合。相比仅修计数，这也能消除尚无助手结果时的临时错位。
3. 实时状态携带 activeTurnId，投影提供身份到编号的映射。匹配活动身份优先于聊天估算编号；新回合尚未被轮询到时放在当前历史之后，不回填到旧回合。已持久化相同步骤结果后隐藏 partial。
4. 在每个事件前缀上重建投影，验证编号、输入归属与分段合并；浏览器回放验证真实组件在轮询与流式更新交替时的顺序。

## Risks / Trade-offs

- [风险] 旧会话缺少 turn_start → 用户消息仍可建立回合，legacy_index 保持原有排序。
- [风险] 历史快照与流式消息不同步 → 以稳定身份匹配；明确已完成步骤后抑制残留 partial。
- [风险] 工作区存在大量其他改动 → 本次仅改相关轨迹文件、实时状态字段和测试，不提交其他改动。
