读取计数器补证：100MB 会话恢复的压缩点后缀扫描只读 973,218 字节、解析 67 条记录，整个 resume 读 975,158 字节；50MB 旧历史加小后缀的单测断言读取少于 256KiB、最多解析 3 条记录。

100MB 首屏缩短约 96.4%，首次历史流量减少约 99.2%。两种总长度的尾页均约 1.61MB/18ms，首屏均约 0.28 秒。保留的完整历史接口仍与文件总长度相关（100MB 约 1.05 秒），这属于显式兼容路径。

实际浏览器向前翻页：已加载行的 ID 保留，原行位置变化 -0.375px；无浏览器异常。新字节链接与旧序号链接均落到原始第 24 条记录对应的第 5 条用户消息，位置 158392。新链接请求目标到当前 before 的连续区间；旧链接由服务端换算后读取目标到文件尾，均未把隐藏检查点当可见消息计数。

旧实现错位复现：直接加载 HEAD 的 sessionTranscript.js，在每条用户消息后都有隐藏文件检查点的三轮数据上，第三条用户的原始序号是 4，前端输出 2。新测试覆盖索引重建、增量追加、HTTP ordinal/position 对齐与导航历史传递，字节位置使用字符串避免 JS 精度损失。

稳态 30 秒的列表流量为 37,898 字节（计时边界落入 7 轮刷新，14 个列表请求）；没有重复 WS 状态订阅。前后对照请看 stage1-sidebar.md，不把采样边界带来的请求轮数差异当优化收益。

## 后续阶段门槛评估

- 阶段 3：合成数据工作区 1500 会话，首次有界列表 109ms，加载期间 4ms。当前证据未达到有界列表 500ms 门槛；没有用户现场 p95 或“2000 会话工作区常见”的证据。旧序号跳转只在显式导航时顺扫，已通过实际浏览器验证。暂不创建 add-session-index-cache，后续根据诊断现场数据决定。

全量验收结果追加到 final-validation.md；上述性能测试不替代完整测试。

## 全量验收中发现的调整

R12 文件行数闸门要求不扩大已有超长文件，因此把 SessionManager 的历史读取、显示快照与文件检查点查询集中到 session_manager_history.cpp；目录元数据投影抽到 global_session_catalog_meta.hpp。未提高任何上限。静态检查仅枚举 Git index 中的文件，验证时使用临时 index 纳入所有当前新源文件，真实 index 不变。

延迟预热后搜索首次返回 progress.complete=false 是既有渐进接口允许的状态。两个旧 smoke 在首个响应就断言已有命中，现改为等待明确的 complete 信号，再保留原文、附件和字面加号/百分号断言。

首次 8 并发 CTest 使用共享的 C:/Users/... 临时目录，该路径在本机映射到 N:，引发路径比较和多个用例写同一隔离配置的失败。改用 N:/acecode-gtest-iso 下的物理路径后，71 项代表性失败用例全部通过，包括配置恢复、StateFile、文件工具、TUI 恢复及原生覆盖层；最终测试结果以隔离复验为准，不据初轮噪声修改产品行为。
