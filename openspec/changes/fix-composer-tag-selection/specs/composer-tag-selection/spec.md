## Purpose

为聊天输入框中的文本与命令、技能、路径、会话及附件 tag 定义一致的选择和编辑行为，使用户在 Windows 上可以通过常规鼠标及键盘操作组合上下文引用，并可靠地复制、删除、替换和撤销这些输入内容。

## ADDED Requirements

### Requirement: 文件输入共享路径与编辑行为
系统 MUST 让拖入、粘贴和选择器取得的同一本地文件使用相同路径 tag、完整引用路径及编辑行为。桌面无源路径数据 MUST 先保存在本地再引用，只有纯 Web 文件输入 SHALL 使用上传。

#### Scenario: 文件同时携带文本格式
- **WHEN** 用户粘贴包含原生文件和文本表示的剪贴板
- **THEN** 系统仅插入文件路径 tag，不重复插入文本或上传附件

#### Scenario: 选择文字与 tag 后插入多个文件
- **WHEN** 用户选中混合内容后拖入或粘贴多个文件
- **THEN** 相同事务按来源顺序替换准确选区，一次撤销恢复原内容，随后可以直接输入

#### Scenario: 原生剪贴板读取失败
- **WHEN** 桌面剪贴板桥接读取失败
- **THEN** 系统显示错误，保留草稿，不将读取失败视为空剪贴板或改走上传

#### Scenario: 桌面截图没有原文件路径
- **WHEN** 用户在桌面端粘贴仅包含图片数据的截图
- **THEN** 系统将数据保存到本地并插入路径 tag，不调用上传接口

#### Scenario: 纯 Web 文件传入
- **WHEN** 普通浏览器中通过拖入或粘贴添加 File
- **THEN** 两种入口共享附件上传流程，不把浏览器文本中看似本地的路径当作服务器文件

#### Scenario: 异步期间继续编辑或切换任务
- **WHEN** 文件解析完成前用户继续输入、移动光标或切换任务
- **THEN** 插入位置随原草稿编辑移动，完成后不覆盖新输入或抢回光标，旧任务结果不写入新任务

### Requirement: 拖入文件后可直接继续输入
系统 MUST 在接收有效外部文件释放时恢复当前 composer 所属窗口的键盘焦点，并 MUST 保留完整引用路径和 tag 后的合法光标。

#### Scenario: 进入时窗口激活未成功
- **WHEN** Windows 拖放进入时的前置尝试没有成功，用户随后在 composer 接收范围内释放文件
- **THEN** 系统在接收文件时再次使用文件拖放专用桥接恢复窗口焦点
- **AND** 用户无需额外点击即可继续输入文字、移动光标或使用中文输入法

#### Scenario: 解析期间用户切换窗口
- **WHEN** 有效文件已经释放，用户在异步路径解析或上传期间切换到其他窗口
- **THEN** 后续异步完成与布局刷新不再次请求原生窗口前置

#### Scenario: 无效或禁用的原生拖放
- **WHEN** composer 已禁用或原生回调没有有效的最近拖放落点
- **THEN** 系统不因该回调抢占窗口焦点

### Requirement: tag 参与原子选择与混合选择

输入框 SHALL 允许单独选中 tag，以及通过鼠标拖选和 Shift 加方向键选择文本与多个 tag，选中样式与后续操作范围一致。

#### Scenario: 单独选中 tag
- **WHEN** 用户单击一个 tag 的主体
- **THEN** tag 作为完整的原子项选中，可以复制、剪切、删除或用文字替换

#### Scenario: 双向混合选择
- **WHEN** 用户从文字或 tag 开始向前或向后拖选，或使用 Shift 加方向键扩展选区跨越多个 tag
- **THEN** 系统保留选区方向及文字边界，跨过的 tag 整体纳入选区

### Requirement: 普通左右键按单个字符越过 tag

输入框 SHALL 在折叠光标处使用无修饰左右键时直接越过相邻 tag，不产生 tag 选区；每次只越过一个原子项，不额外跳过文字、空格或相邻 tag。方向 SHALL 与段落的文字方向一致。

#### Scenario: 从 tag 两侧移动并继续输入
- **WHEN** 光标紧邻任意类型 tag，用户按朝向 tag 的普通左右键
- **THEN** 光标直接落在 tag 另一侧，tag 不高亮，随后输入插在该边界而不替换 tag

#### Scenario: 连续 tag 与段落边界
- **WHEN** 输入框包含无空格相邻 tag、行首或行尾 tag
- **THEN** 每次按键只越过一个 tag，可在两个 tag 之间停留，不跳过换行或移出文档

#### Scenario: 选择与组合键不被普通移动接管
- **WHEN** 已有选区，或用户按 Shift/Ctrl/Alt/Meta 加方向键，或输入法正在组合
- **THEN** 原有选区折叠、原子扩选、单词与行级导航及输入法行为保持不变

### Requirement: tag 使用正文排版与原生选择颜色

输入框 SHALL 将 tag 渲染为无背景和边框的主题色文本，与正文共享字体、字号、行高和基线，仅稍加粗。选中时 SHALL 使用与正文一致的矩形背景与前景色，且不触发颜色过渡或布局变化。

#### Scenario: 拖选与键盘混选的视觉一致
- **WHEN** 用户拖选或通过 Shift 加方向键选择文字、空格和多个 tag
- **THEN** 这些内容背后的矩形选区连续且上下对齐，tag 文字和图标使用选择前景色，换行时各行选区仍然完整

#### Scenario: 取消选区
- **WHEN** 用户将选区折叠成光标或输入框失去焦点
- **THEN** tag 选区背景消失，恢复主题色，不发生布局跳动

### Requirement: 混合选区编辑保持引用与历史

输入框 SHALL 对选中的文字和 tag 执行一致的复制、剪切、删除和替换，撤销与重做保持引用顺序和周围未选内容。

#### Scenario: 复制与剪切
- **WHEN** 用户复制或剪切单个 tag 或混合选区并粘贴回可解析引用的输入框
- **THEN** 文本与 tag 的内容和顺序保留，剪切只删除选中的内容

#### Scenario: 删除及撤销
- **WHEN** 用户删除或替换选区后撤销并重做
- **THEN** 原始文本和 tag 可恢复，未选中的内容不丢失

### Requirement: 自动命令转换可撤销

输入框 SHALL 保留命令从文字自动转换为 tag 时的撤销历史。

#### Scenario: 输入命令并转换
- **WHEN** 用户输入已知命令及确认空格后使用 Ctrl+Z 和 Ctrl+Y
- **THEN** 撤销恢复此前编辑状态，重做恢复命令及 tag，不发生无效撤销或节点路径错误

### Requirement: 选择手势不触发附件动作

输入框 SHALL 保留附件预览与移除能力，选择或拖选 tag 不得误触这些动作。

#### Scenario: 从图片 tag 拖选
- **WHEN** 用户从图片 tag 主体开始拖选到周围文字
- **THEN** 形成混合选区，图片预览不自动打开，附件不被移除
