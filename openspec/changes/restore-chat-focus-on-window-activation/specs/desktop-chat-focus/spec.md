## Purpose

保证桌面应用从其他程序切回、从最小化恢复或切换窗口显示状态时，当前可用聊天输入框立即具备真实键盘输入能力，用户不必再次点击；同时保护现有草稿、选区与阻塞弹框交互。

## ADDED Requirements

### Requirement: 窗口激活恢复聊天输入

Windows、macOS、Linux 桌面端 SHALL 在窗口重新获得焦点，或活动窗口完成最大化/恢复后，将键盘焦点交给当前可用聊天输入框。之前位于终端或预览中的焦点 MUST NOT 阻止恢复。

#### Scenario: 从其他程序切回
- **WHEN** 用户通过 Alt+Tab 或平台对应操作切回有聊天输入框的窗口
- **THEN** 用户无需鼠标点击即可继续输入，已有草稿和有效选区保留

#### Scenario: 恢复或最大化
- **WHEN** 用户从最小化、隐藏状态恢复聊天窗口，或最大化/还原活动窗口
- **THEN** 聊天输入框接收随后键入的文字

### Requirement: 恢复只作用于当前可用聊天

系统 MUST 取消过期恢复，不得拉前后台窗口、聚焦已卸载或隐藏的聊天，或覆盖阻塞弹框中的输入；普通窗口内控件切换 MUST NOT 触发持续抢焦点。

#### Scenario: 快速切走
- **WHEN** 恢复仍在等待执行，用户又切到其他窗口
- **THEN** 过期恢复不改变当前窗口或输入位置

#### Scenario: 阻塞表面打开
- **WHEN** 设置、搜索、提问或模态框正在占用输入
- **THEN** 底层聊天不夺取焦点

#### Scenario: 激活后继续其他操作
- **WHEN** 用户已经恢复窗口并主动点击其他控件或输入文字
- **THEN** 尚未执行的重复恢复被撤销，不影响本次交互

#### Scenario: 中文输入期间收到恢复通知
- **WHEN** 中文输入法处于合成或提交结算阶段，窗口再次通知激活，或上一轮延迟恢复到达
- **THEN** 系统 MUST 保留原生合成与可见光标，不重新聚焦 WebView 或编辑器，不提前提交、重复插入或移到其他位置

#### Scenario: 无键盘事件的文本输入
- **WHEN** 输入法或原生输入服务以 beforeinput / input 更新文本而没有 keydown
- **THEN** 待执行的焦点恢复 MUST 被撤销，后续文字沿可见光标继续插入
