## Context

动机见 proposal.md。当前 ChatView 保持挂载，文件页签按 workspace/worktree 索引；SidePanel 的树按 cwd，面板布局和终端停靠参数为全局偏好，PTY 注册表也无会话归属。未保存确认已有单请求控制器。

## Goals / Non-Goals

**Goals:** 所有本次列出的工作状态归属统一、切换立即恢复、异步回包不得污染新会话；保留既有确认和文件版本校验；覆盖同工作区及跨工作区场景。

**Non-Goals:** 主题、语言、字体、默认 Shell 等应用配置仍为用户设置；磁盘文件和仓库本身不复制；无需将原生浏览器登录 profile 变为新的账户系统。

## Decisions

1. 建立以会话 ID 为稳定归属的工作状态存储和 React 订阅适配。setter 捕获归属，读状态无需等待切换后的 effect 清空。工作目录继续作为会话内部资源标识，worktree 变化不改变会话身份。可序列化浏览状态保存在当前浏览窗口的 sessionStorage，Map/Set 保留类型；存储失败不影响内存操作。
2. 文件页签集合改为会话与目录联合索引，删除工作区活动项回退。关闭/草稿/刷新使用相同索引；新建交接显式重映射页签键、顺序与活动项。仅在界面隐藏别人的 tab 不足以保证关闭和异步更新安全。
3. 文件树、Git 基线、列表形式、滚动和详情显示通过同一存储分字段维护；每会话的 Git 导航与详情共享该会话缓存。目录变化使用会话内部 cwd 索引。Git/文件变更事件失效相关物理目录的数据，但不修改其他会话的交互状态。侧边栏、导航、预览和子代理面板的宽度及预览手动尺寸标记由 App 的单个 usePreference 保存到 `acecode.singleLayoutWidths.v1`，不绑定会话。恢复旧工作状态时丢弃已停用的 `layout` 字段，其他会话状态继续恢复。
4. 未创建会话的入口获得独立临时 owner；正式创建后原子移交并轮换新建入口。迟到的操作仍对应原归属，不能写入下一个新建入口。聊天输入草稿使用现有接受回执机制，不复制给已有会话。
5. PTY 创建与列表协议增加 owner，注册表提供临时 owner 到正式会话的移交；移交别名覆盖在途创建。前端保留各终端实例、输出与连接，按当前 owner 显示 tab，切换不删除进程。旧版无 owner 的终端不自动分给任意会话。
6. 保留未保存确认，提交原动作前同步清除 dirty；错误、取消、双击和迟到回包均定向验证。文件保存继续走既有 read_id 接口。

## Risks / Trade-offs

- [切换后异步结果写错位置] → setter 捕获 owner，组件异步请求带归属或在挂载边界取消；同名文件和同 cwd 回包分别测试。
- [新建交接期间丢终端] → 前后端明确移交并处理迟到创建；不以卸载组件关闭 PTY。
- [全局宽度与会话状态混用] → 宽度只读写全局偏好，切换会话、新建入口和工作区不会覆盖；面板显示、最大化、页签及终端状态继续归属会话。
- [浏览缓存序列化容量] → 写入合并、失败保留内存；原生终端输出不进入浏览存储，由 PTY 回放。

## Migration Plan

先完成纯状态与单测，再接入预览/面板/Git，再接入 PTY 与新建交接；最后用 A 五页签、B 两页签往返及真实 PTY 验证。旧工作区共享文件集合不能无依据复制给所有历史会话；新索引使用独立存储版本。原未保存确认保持可用。
