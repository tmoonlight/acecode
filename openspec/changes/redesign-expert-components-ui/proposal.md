## Why

ACECode 已有专家派遣、专家团和会话内切换能力，但专家目录仍混淆“擅长领域”与“开场白”，管理表单也缺少 Tag、Skill、MCP 与本地工具的完整配置入口。导入的 Claude 高保真稿与现有需求文档已经明确了统一体验，现在需要把所有专家相关界面、数据模型和运行时约束一起落地，避免只换视觉而能力配置失真。

## What Changes

- 重做专家组件页的信息架构和视觉：专家/专家团主页签、可复用的多选 Tag 筛选、搜索与排序、展示“擅长领域”的卡片、专家详情弹窗和响应式布局。
- 统一专家详情和派遣流程：详情展示能力介绍、擅长领域及可点击开场白；开场白只回填真实聊天输入框、不自动发送；所有使用动作统一为“派遣”。
- 保持所有对话共用的“+”菜单入口，并规范二级菜单为最近使用的专家/专家团（合计最多 5 个）及“更多专家”；空历史不显示占位文案，派遣和聊到一半切换均不切屏。
- 重做专家与专家团编辑体验：基础信息与高级功能页签；Tag、擅长领域、开场白按多值语义编辑；专家团支持成员、主理人和成员管理。
- 为专家增加可持久化的 Skill、MCP 服务和 ACECode 本地工具选择；高级功能页展示实时可选项与状态，而不是写死演示数据。
- 在运行时按当前专家确定 Skill、MCP 和本地工具可见范围；专家显式配置优先于全局启用/禁用状态，但仍不得绕过权限确认、Plan/Dangerous 模式、沙箱或凭空创建未安装/未配置的能力。
- 专家组件管理页的 `派遣` 直接回到新建任务并挂载所选专家，不再要求选择已有目标对话；所有新建任务和已有会话的专家状态旁提供 `×`，用于只解除会话绑定而不重建当前 AgentLoop 上下文或影响 KV cache。
- 保留既有专家包资源和未知字段，兼容现有专家数据与会话绑定；补齐前后端测试、构建与真实浏览器视觉验收。
- 专家组件页明确不新增、模拟或悬浮任何聊天框。

## Capabilities

### New Capabilities

- `expert-discovery-and-dispatch`: 专家/专家团目录、Tag 筛选、卡片与详情、开场白回填、共享最近记录、真实聊天框派遣及会话内无切屏切换。
- `expert-authoring-and-teams`: 专家基础信息、擅长领域、开场白、工作方式以及专家团成员/主理人的创建和编辑契约。
- `expert-capability-scoping`: 专家对 Skill、MCP 服务和本地工具的选择、持久化、状态呈现、显式配置优先级及不越过安全/权限边界的运行时约束。

### Modified Capabilities

无。当前工作树没有已发布的 `openspec/specs/` 专家能力规范；本变更将现有实现行为正式收敛为上述新能力。

## Impact

- WebUI：专家组件页、专家详情/编辑弹窗、聊天输入栏“+”菜单、当前专家状态展示、前端数据归一化和 API 客户端。
- C++：专家包数据模型与序列化、专家 CRUD/API DTO、会话绑定/轻量解除绑定、Skill/MCP/本地工具的运行时过滤和能力目录接口。
- 数据兼容：已有专家包和已有会话继续可读；更新专家时必须保留未被当前表单编辑的资源与未知字段。
- 验证：C++ 单元测试、Web 单元测试与构建、桌面尺寸和窄屏真实浏览器视觉/交互检查。
