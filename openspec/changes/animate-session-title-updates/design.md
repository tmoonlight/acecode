## 背景

两处标题均由服务端 title / summary 派生，分别在 transcript 与 Sidebar 中消费 session_updated。侧栏已有测量溢出与悬停滚动，顶部既支持内联也支持 portal。

## 目标与边界

让标题更新可见，并保持两处播放进度一致。动画仅属于展示层；持久化标题、可访问名称、编辑初值始终是完整文本。

## 决策

1. 按会话作用域和 ID 共享短生命周期的动画状态，React hook 只在同一已加载会话的标题发生变化时启动。初次挂载与历史加载直接显示完整标题，订阅释放后清理计时与状态。
2. 按字素逐步呈现，约每字 28ms，总时长限制为 180–650ms。开始显示第一个字并跟随黑色方块光标，最后一个字完成时立即移除光标，不附加闪烁循环。深色背景提供细浅色边缘，使黑色方块仍然可辨。旧 WebView 缺少字素分割能力时直接显示完整文字，避免截断复合字符。
3. 共享文字组件使用不可见完整文本稳定测量宽度，视觉层展示当前进度，避免标题栏工作区标签随打字移动。完整文字供辅助技术读取，视觉层与光标隐藏于可访问树。
4. 打字期间暂停侧栏跑马灯，完成后恢复原有溢出行为。减少动态效果时将逐字反馈缩短至最多 320ms，保留不闪烁的短暂光标；页面处于后台时直接完成。已有编辑流程与鼠标键盘事件保持原样。

### 2026-10-12 实机修正

运行中的 Desktop 服务已经返回含打字组件的前端，而 Windows `SPI_GETCLIENTAREAANIMATION` 返回 false。上一版将减少动态效果直接映射为完全跳过打字，违背了用户需要感知改名的目标。修正为更短的非位移动效，不改 Windows 设置；验证必须包含 reduced-motion 模式下的可见中间帧，而不只是普通模式。

### 2026-10-12 标题同步修正

真实 transcript hook 复现：正文事件 seq=20 先到时，后到的首次标题通知 seq=19 被全局 lastSeq 丢弃，侧栏没有这道过滤。对 title 与 summary 分别记录最后接受的事件序号；正文水位继续维持原去重规则，旧标题不能覆盖新标题，旧蜂群模式不随放行的标题更新回退。

同时为历史请求捕获发出时的状态，按字段修订号保护请求期间到达的标题与摘要（包括用户清空）。初始历史、补拉响应及游标失效重载均采用该规则；请求发出前的元数据仍可被更新快照替换，不把标题永久锁死。

## 风险与处理

- 不同数据源到达时间不同：共享同一会话的目标文本与进度，重复更新不会重置计时。
- 历史加载被误判为改名：顶部在 transcript 加载完成之前仅建立基线；切换身份重置观察。
- 快速重命名与组件卸载：新目标覆盖旧动画；最后一个订阅移除时取消调度。
- 源码验证与安装版不同步：执行 Web 测试、构建及浏览器验证，单独说明未重建的 Desktop。
