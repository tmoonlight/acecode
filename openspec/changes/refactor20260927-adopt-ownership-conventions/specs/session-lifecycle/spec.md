## ADDED Requirements

### Requirement: 会话销毁与宿主关停时释放会话资源
会话被单独销毁、或所在宿主关停时,系统 MUST 对每个活跃会话依次:中止正在运行的回合;停止该会话的 agent 循环并等待其工作线程结束;完成最终的元数据写入;释放写者租约,即删除租约文件。宿主指 daemon、TUI 的子代理宿主、headless 进程。

最终元数据写入 MUST NOT 改变该会话的 `updated_at`,会话列表的排序因此保持不变。

对仍在等待用户应答的提问或权限请求,系统 MUST 以「已取消」收尾,不得让任何线程无限等待。

宿主关停一旦开始,系统 MUST 拒绝新建会话和恢复会话的请求,并返回明确的错误。

对已进入会话队列、但尚未开始执行的控制任务,系统 MUST 丢弃,不再执行。等待这些任务完成的调用方 MUST 及时得到「未执行」的结果,不得挂死。

#### Scenario: daemon 退出时有活跃会话
- **WHEN** daemon 退出时仍有 3 个活跃会话,其中 1 个回合正在运行
- **THEN** 运行中的回合被中止,3 个会话的 `.meta.json` 都完成最终写入且 `updated_at` 保持原值
- **AND** 这 3 个会话的写者租约文件都已删除,另一个进程可以立即接管,无需等待 PID 失效或心跳过期

#### Scenario: 关停时有挂起的提问
- **WHEN** 某会话正阻塞在 AskUserQuestion 等待用户应答,此时宿主开始关停
- **THEN** 该提问以「已取消」收尾,会话的工作线程正常退出
- **AND** 进程正常结束,不崩溃,不卡死

#### Scenario: 关停开始后新建会话
- **WHEN** 宿主已开始关停,此时收到新建会话或恢复会话的请求
- **THEN** 系统拒绝该请求并返回错误,不创建任何会话文件

#### Scenario: 关停时队列中有未执行的控制任务
- **WHEN** 会话忙于一个回合时,又排入了刷新沙盒配置的控制任务,随后该会话被销毁
- **THEN** 该控制任务不会执行
- **AND** 等待它完成的调用方及时得到「未执行」的结果,不挂死
- **AND** 会话对象在销毁后被完整释放,不因控制任务持有引用而残留
