## Purpose

定义提示词相关配置在一个回合内的生效时机:同一回合内的所有模型请求使用同一份配置快照,既保证请求前缀的字节稳定(利于提示词缓存),也消除配置在回合中途被整份替换时的并发读写风险。

## ADDED Requirements

### Requirement: 提示词相关配置以回合为单位生效
系统 MUST 在每个回合开始时,把提示词相关配置捕获为一份不可变快照。纳入快照的配置有:
- 自定义指令;
- 项目指令的配置项:是否启用、文件名列表、字节与深度上限等;
- 记忆配置;
- git 上下文配置;
- 当前生效的技能注册表;
- 专家定义。

同一回合内的所有模型请求 MUST 使用这份快照,包括工具往返后的后续请求、重试请求、回合内自动压缩后的请求。

回合进行中对上述配置的修改,MUST 从下一个回合开始生效,不得影响当前回合剩余的请求。

本需求只约束配置对象本身。项目指令文件内容的重新读取,仍然按 `project-instructions` 能力的既有规则进行。

#### Scenario: 回合中途修改自定义指令
- **WHEN** 一个包含多次工具往返的回合正在进行,用户在设置页修改了自定义指令并保存
- **THEN** 当前回合剩余的模型请求仍使用回合开始时的自定义指令,请求前缀逐字节不变
- **AND** 下一个回合的请求使用新的自定义指令

#### Scenario: 回合中途切换专家
- **WHEN** 回合进行中,用户为该会话切换了专家
- **THEN** 当前回合继续使用切换前的专家定义与技能集合
- **AND** 切换从下一个回合开始生效

#### Scenario: 空闲时修改配置
- **WHEN** 会话空闲时用户修改了记忆配置或 git 上下文配置
- **THEN** 下一个回合开始时捕获的快照已包含修改后的配置
