## Purpose

让 ACECode 的公开下载目录随安装包发布自动更新，用户无需在本机执行刷新命令。
目录只展示已公开的版本资产，并在部署后验证 CDN 实际内容，保证发布记录与用户看到的文件一致。

## ADDED Requirements

### Requirement: 发布成功后自动更新下载站

系统 SHALL 在 GitHub Release 安装资产发布成功后自动刷新并部署公开下载清单。

#### Scenario: 标签发布成功
- **WHEN** 标签对应的安装包发布步骤成功
- **THEN** 自动执行公开目录同步和 Pages 部署
- **AND** 全过程不依赖用户电脑开机

#### Scenario: 发布失败或非标签打包
- **WHEN** 安装包发布失败或运行普通分支打包
- **THEN** 不执行本次发布的网站同步

### Requirement: 验证公开版本与同步结果

系统 SHALL 拒绝缺失、草稿或没有完整下载校验值的目标版本，并在有限时间内确认 CDN 清单与生成结果一致。

#### Scenario: 无效目标
- **WHEN** 请求同步的版本未公开或资产缺少有效 SHA-256
- **THEN** 同步失败且不推送不完整目录

#### Scenario: CDN 尚未更新
- **WHEN** Pages 部署失败或 CDN 未在等待期限内提供目标目录
- **THEN** 发布流程的网站同步步骤明确失败，已有安装包与旧网页继续可用

### Requirement: 重试与授权边界

系统 SHALL 只使用公开站点仓库的专用写入授权，串行处理同步并允许同版本安全重试。

#### Scenario: 相同内容重复执行
- **WHEN** 重新运行同一版本同步且目录内容未变
- **THEN** 不创建空提交，并继续验证 CDN 目录

#### Scenario: 旧版本重新运行
- **WHEN** 已有更新版本后重试旧版本同步
- **THEN** 仍读取所有已公开 Release，不能把当前下载目录回退到旧版本
