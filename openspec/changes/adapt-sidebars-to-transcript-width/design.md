## Context

App 持有全局左栏开关、按工作台保存的右栏开关和全局栏宽；ChatView 持有预览页签、预览隐藏与子对话状态。现有布局求解器允许 transcript 缩到 350 px。动机见 proposal.md。

## Goals / Non-Goals

- 以 transcript 为优先级最高的常规阅读区域，计算窗口、预览、导航与子对话共同产生的占宽。
- 不迁移偏好存储作用域，不改后端，不修改用户已有的手动最大化/演示模式语义。
- 自动隐藏保留组件、页签和草稿；不把临时显示状态写进工作台或全局偏好。

## Decisions

1. 按用户调低折叠阈值的要求，所有字号的阅读下限统一为 350 CSS px。恢复门槛比折叠门槛高 64 px；使用壳体实际宽度、保存栏宽和预览意图预测展开后的 transcript 宽度，避免用收起后变宽的 transcript 直接触发反向展开。
2. 独立纯函数决定左右自动折叠与可停靠能力；React hook 只负责测量、临时状态与外部点击。左栏优先保留，右侧预览和列表作为一组让出空间。子对话打开时，父 transcript 的预算额外考虑子对话宽度。
3. 只由正常布局下的手动开关修改现有偏好。popup 互斥、切工作台清空，窄窗口刷新重新按偏好计算。宽度恢复后，原先开启的栏停靠，原先关闭的栏保持关闭。
4. 左右 popup 保留原组件实例，不用改变 portal 目标的方式搬运内容。通过 React 事件边界识别栏内 portal 菜单，防止操作栏内菜单被误认作外部点击。Escape 尊重内层菜单/对话框的处理。
5. 窄右侧 popup 同时有详情与列表时，以详情为主，列表可临时覆盖详情供选择；不能因两个最小宽度相加而把浮层撑出窗口。临时列表开关也不修改持久化偏好。
6. 现有显式预览最大化/演示模式继续生效；自动折叠只保护常规对话布局，不能把用户主动最大化误当成挤压。
7. Desktop 的原生最小窗口宽度由旧的 1170 降为 480 逻辑像素，低于左栏自动折叠门槛。Windows 继续按 DPI 缩放并受工作区上限约束；macOS 拖动和程序化设置宽度共用此下限。初始窗口大小保持现有设置。原生下限与 transcript 的阅读下限分开，用户主动缩到更窄时由前端使用全部可用空间。
8. 浮层也提供靠 transcript 一侧的拖宽手柄：左浮层拖右边，右浮层拖左边。使用实际渲染宽度作为拖动起点，范围由当前容器和 24 px 外部点击区域计算。浮层手动宽度保存在同一个全局栏宽偏好中的可选 `sidebarPopup` / `rightPanelPopup` 字段，不改正常占位宽度和开关；拖窄不会因此退出浮动或压缩 transcript。默认仍使用现有栏宽，窄视口临时夹取不能覆盖保存值。Pointer capture 保持跨边界拖动，取消、失焦、关闭或卸载均清理监听与拖动光标；键盘方向键沿用原手柄步长。

## Risks / Trade-offs

- 收起后测量反馈环 → 根据未受临时隐藏影响的意图计算，并保留恢复余量。
- popup 关闭导致编辑草稿丢失 → 自动隐藏保留挂载；对既有草稿存储做回归验证。
- 老 WebView 不支持新 CSS → 使用普通绝对定位、现有颜色变量与 rgba 阴影。
- Desktop 运行包可能仍使用旧前端 → 本次验证源码、构建和 Chromium；不把这些证据宣称为已安装 Desktop 已更新。

## Migration Plan

无需存储迁移；已有偏好即为恢复依据。撤回前端变更即可回滚，临时状态不会污染保存数据。
