## 为什么

Desktop 的文件详情目前只能查看，用户若要修改文本必须切换到外部编辑器；Markdown 也只能在渲染结果与源码之间查看，无法直接在排版内容中编辑。同时，详情标签缺少草稿状态和快捷入口，关闭详情面板还会误导用户清空全部标签，与常见编辑器的工作台习惯不一致。

## 变更内容

- 为当前注册工作区及当前 worktree 内的安全文本文件提供打开即编辑、源码显色、`Ctrl+S` 保存、关闭时保存选择、编码与换行保真、版本冲突保护。
- 为 Markdown 提供默认所见即所得的轻量编辑器，支持常用正文格式和已有表格文字编辑；复杂结构保持可见并原样保留，不扩展为完整排版工具。
- 在有未保存草稿的文件标签上显示实心“大点”，并阻止标签关闭、批量关闭或面板生命周期静默丢失草稿。
- 在详情标签栏旁增加“+”入口，左键菜单固定提供“终端”“浏览器”“侧边聊天”三个操作，并复用现有工作区/会话打开路径。
- 将详情面板右上角关闭动作改为只隐藏面板并保留全部标签；只有用户明确在标签栏执行“全部关闭”等标签操作时才清理标签，并继续保护未保存草稿。
- 图片、PDF、Office、二进制、超出文本大小限制的文件以及显式打开的工作区外路径继续只读。

## 能力

### 新能力

- `desktop-file-editing`：Desktop 文件详情中的普通文本编辑、Markdown 轻量所见即所得编辑，以及安全保存与冲突处理。
- `preview-tab-workbench`：详情标签的草稿状态、快捷新建菜单、隐藏/恢复语义和显式标签关闭行为。

### 修改能力

- 无。

## 影响

- WebUI：`FilePreviewContent.jsx`、`PreviewDetailsPanel.jsx`、`ChatView.jsx`、`previewTabs.js`、API 客户端、样式及相关测试。
- 服务端：文件路由与处理器、安全文本缓冲、写锁/版本检查、Desktop 管理模式与工作区边界。
- 前端依赖：复用现有 Slate 与 GFM Markdown 解析依赖；若直接调用 Markdown 序列化包，将其声明为直接依赖。
- 协议：新增经过认证且仅限 Desktop 可写范围的文本读取元数据与保存接口；冲突返回 `HTTP 409`。
- 文档：更新 Desktop 文件详情与文件 API 行为说明。
