## 背景

当前文件详情由 `FilePreviewContent.jsx` 读取 `/api/files/content` 或 `/api/files/blob` 后只读渲染；`PreviewDetailsPanel.jsx` 只挂载活动标签内容，`ChatView.jsx` 与 `previewTabs.js` 保存标签集合但没有编辑草稿。详情面板右上角叉号调用“关闭全部标签”，浏览器标签还会同步销毁原生页面。

代码库已经具备可复用的安全基础：`text_file_buffer` 能严格解码并保留编码、BOM、换行，执行写后回读与失败回滚；`MtimeTracker` 提供单文件写锁；WebUI 已安装 Slate、GFM Markdown 解析依赖；`ChatView` 已有浏览器入口和 `/api/sessions/:id/side-question` 旁路提问能力；顶层 `App` 已有终端 Dock 开关。

## 目标 / 非目标

**目标：**

- 在 Desktop 文件详情中安全编辑工作区内的普通文本，并让 Markdown 默认进入轻量所见即所得编辑体验。
- 草稿跨标签切换、详情隐藏和组件重新挂载继续存在，以实心圆明确显示未保存状态。
- 使详情标签栏的“+”成为终端、浏览器和侧边聊天的统一入口。
- 把详情面板的“隐藏”和标签的“关闭”拆成两个明确动作。

**非目标：**

- 不允许通过该接口创建、重命名、删除文件，也不扩大目录、Git 或任意外部路径的写权限。
- 不把 Markdown 编辑器扩展成完整排版软件；不提供字体、颜色、对齐、图片上传/缩放、表格结构设计或复杂嵌入编辑。
- 不把现有聊天 `RichComposer` 改造成文档编辑器，也不为侧边聊天新增常驻 Sidebar 或持久化第二套聊天会话。
- 不编辑图片、PDF、Office、二进制、无法严格识别编码或超过 5 MiB 的文件。

## 决策

### 1. 将编辑草稿放在预览标签状态中

文件标签增加编辑状态，至少保存基线文本、草稿文本、`read_id`、是否编辑、是否脏、是否检测到外部变化和最近保存错误。`FilePreviewContent` 只负责渲染和上报变化，标签状态由 `ChatView` 通过 `previewTabs.js` 的纯函数更新。

这样切换活动标签、切换到浏览器标签或隐藏详情面板时不会丢失草稿。把草稿留在 `FilePreviewContent` 本地状态的方案被否决，因为详情面板按可见性卸载，浏览器/变更标签也会卸载文件内容。

### 2. 新增 Desktop 专用的严格文本读写接口

新增 `/api/files/editable`：

- `GET` 仅接受已注册工作区或活动 worktree 内的既有文件，严格读取 `TextFileBuffer`，返回 LF 归一的 UTF-8 文本、`read_id`、编码、换行和大小。
- `PUT` 接受 `cwd`、`path`、`text` 与调用方读取时的 `read_id`。服务端在 `MtimeTracker::acquire_write_guard` 内重新读取文件并比较内容版本；不一致返回 `HTTP 409`，一致才调用 `safe_write_text_file`，沿用磁盘上的编码、BOM 和换行。
- 路由要求认证且 `WebServerDeps::desktop_managed` 为真，并继续经过 `validate_path_within` 与 5 MiB 限制。工作区外的显式预览仍只读。
- 成功保存后清除该路径的 Agent 读取基线与重复读取观察，防止模型把人类刚写入的内容误当成自己已经读取的基线；同时使相关会话的 Git 快照失效。

继续直接复用只读 `/api/files/content` 并由前端回传编码元数据的方案被否决：客户端元数据不可信，也无法在写锁内保证版本与编码属于同一磁盘快照。

### 3. 编辑能力嵌入原预览表面，Markdown 使用独立 Slate 文档模型

可写普通文本打开后直接在原有源码预览表面编辑，不需要先点击“编辑”。实现使用原高亮渲染层与透明原生输入层叠加，必须保留既有行号、语法显色、复制、自动换行以及选区引用/批注表面；无法识别语言时仍可编辑，只是不额外着色。不得用独立编辑器壳替换原预览，也不得新增保存状态栏。

Markdown 打开后直接在原有排版预览表面进入 `MarkdownWysiwygEditor`，不复用 `RichComposer`：后者的 schema 只有纯文本和行内标签，且承担聊天输入法、补全和附件协议。Slate 的可编辑节点复用原 `ace-md ace-side-markdown-preview` 类与渲染语义，不显示工具栏，不改变标题、正文、引用、列表、表格、代码块和复杂节点在浏览状态下的视觉。

只读渲染节点与 Slate `Editable` 都是预览框中的直接 flex 子项。共享的 `ace-side-markdown-preview` 表面必须参与主轴伸展并占满可用宽度，不能按短内容的固有宽度收缩；修正只作用于共享表面尺寸，不改变原有内边距、滚动或 Markdown 排版。

Markdown 管线为 GFM Markdown → MDAST → Slate → MDAST → Markdown。支持直接编辑段落、标题、粗体、斜体、删除线、行内代码、链接文字、引用、代码块、有序/无序/任务列表，以及已有表格的单元格文字。格式能力通过直接编辑和已有键盘语义提供，不新增格式工具栏。

图片、Mermaid、数学、原始 HTML、脚注、引用定义和未知扩展转换成只读的 opaque 节点，节点保留原始 Markdown 片段并由自定义序列化处理器原样写回。受支持节点允许采用确定性的 GFM 输出；编辑器不得因为不认识某个复杂节点而删除它。`mdast-util-to-markdown` 作为直接依赖声明，避免依赖 pnpm 的传递依赖布局。

原始 `contenteditable` 加 HTML 反向转换的方案被否决，因为选区、中文输入法、粘贴和 Markdown 语义回写都不稳定。整份 Markdown 只用源码框编辑也被否决，因为用户明确要求所见即所得。

原预览的选择引用与批注不是可选附属功能。普通文本的输入层选区必须映射回原高亮内容；Markdown 的 Slate 选区必须映射成既有选择上下文。失焦时仍显示灰色选区，选择动作浮层、引用到聊天、批注编辑器、已完成批注的持久标记、编号气泡和悬停效果都继续工作。对 Slate 内容使用编辑器原生 decoration 渲染标记，避免直接改写 Slate 管理的 DOM；普通静态预览继续沿用既有 DOM 标记机制。

Markdown decoration 可能由一个跨越多条视觉行的行内元素承载。编号气泡必须测量首个标记元素的第一个非空 `ClientRect`，而不能使用覆盖全部换行片段的 `getBoundingClientRect()` 联合矩形；否则后续视觉行从段首开始时，会把气泡错误拉到面板最左侧并偏离选区首行。

### 4. 保存、关闭选择、刷新和冲突不改变常态界面

可写文本加载成功后直接显示编辑器，不显示“编辑”“保存”“取消”按钮。`Ctrl+S` 保存当前文件；成功后更新基线和 `read_id`、保留编辑器并移除大点。脏草稿的标签关闭、关闭其他、关闭右侧和全部关闭均先显示应用内三选确认：“保存并关闭”依次保存目标集合中的脏文件并在全部成功后执行关闭，“不保存”直接丢弃目标草稿并关闭，“取消”保持页签和草稿不变。批量保存任一文件失败时不得关闭任何目标页签，已经成功保存的文件更新为干净状态，失败文件继续保留草稿和错误。详情面板隐藏不确认，因为草稿仍被保留。

正常保存成功不显示“所有更改已保存”等提示，标签大点消失即为反馈。只有保存失败、版本冲突或需要关闭选择时，才使用既有临时提示或确认界面。Agent 自动刷新命中脏标签时不得覆盖草稿，而是保留草稿；最终保存仍由 `read_id` 做权威冲突判断，冲突后保留草稿并提示重新载入或继续复制处理，不提供静默覆盖。

### 5. “+”菜单只负责调度现有表面

在可滚动标签列表与右侧动作区之间加入固定的“+”按钮，左键打开三项弹出菜单：

- “终端”调用 `App` 的终端 Dock 打开回调，只执行打开，不做 toggle。
- “浏览器”调用现有 `createAgentBrowserPage` 与 `openBrowserTab` 流程；原生浏览器不可用时禁用。
- “侧边聊天”在当前 `ChatView` 内展开独立的旁路提问输入卡，发送到现有 `askSideQuestion` 接口。它保存自己的输入草稿，不修改主 `RichComposer` 草稿，也不创建 Sidebar 或第二个持久会话。

菜单使用 portal、点击外部关闭和 `Escape` 关闭，并提供键盘焦点与 `menu/menuitem` 语义。原有单独浏览器动作按钮移除，避免两个入口表达同一操作。

### 6. 详情隐藏与标签清理分离

`ChatView` 增加当前会话的 `previewPanelHidden` 状态。右上角叉号只设置隐藏状态，不调用任何关闭标签或浏览器页面 API；再次从文件树、变更、浏览器活动等入口打开详情时清除隐藏状态并恢复原标签。

标签自身关闭按钮和标签右键菜单继续真正移除标签；“全部关闭”只从标签上下文菜单等显式标签操作进入，并在需要时确认丢弃草稿。该设计让浏览器页面与文件草稿在面板隐藏后都保持活动。

## 风险 / 权衡

- **[Slate 在 WebView2 的中文输入法与选区边界可能异常]** → 保证文档始终至少一个合法段落，组合输入期间不替换外部文档，复用现有 Slate 防护经验，并覆盖中文输入、空文档和切换/隐藏恢复测试。
- **[Markdown 序列化会规范化受支持语法的标记风格]** → 只承诺语义等价；opaque 复杂节点保存原始片段，并用往返夹具证明不会丢失。
- **[大草稿放在 React 标签状态中会增加内存]** → 继续使用 5 MiB 上限，关闭标签即释放草稿，不把草稿持久化到本地存储。
- **[文件可能在同一时间戳粒度内被外部程序修改]** → 冲突依据原始字节派生的 `read_id`，而非只依赖 mtime。
- **[隐藏面板后用户可能不知道标签仍在]** → 下次打开任意详情自动恢复，右上角提示改为“隐藏详情面板”，标签右键仍提供明确的全部关闭。
- **[旁路提问一次只处理一个问题]** → 菜单入口沿用已有后端互斥和结果卡；不在本变更中引入第二套会话生命周期。

## 迁移计划

1. 先加入纯状态、Markdown 转换和后端接口测试，再接入 UI。
2. 新路由只在 Desktop 管理模式开放，不改变现有只读端点响应，因此旧 WebUI 和外部预览不需要迁移。
3. 前端发布后旧标签数据没有编辑字段时按无草稿处理，并在文件重新加载时尝试建立可编辑状态。
4. 若回滚，移除新 UI 和路由即可；磁盘文件仍是标准文本/Markdown，不存在专有格式迁移。

## 开放问题

无。当前范围以用户给出的三张参考图和本设计中的轻量编辑边界为准。
