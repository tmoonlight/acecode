## ADDED Requirements

### Requirement: 工作区文本文件打开后直接安全编辑
系统 SHALL 仅在 Desktop 管理模式下允许编辑当前注册工作区或活动 worktree 内、大小不超过 5 MiB 且可严格解码的既有文本文件，并在加载成功后直接显示编辑器而不要求用户点击“编辑”。

#### Scenario: 工作区普通文本打开即编辑
- **WHEN** 用户在 Desktop 文件详情中打开符合条件的普通文本
- **THEN** 系统直接显示保留语法显色的源码编辑器，并保留读取时的内容版本、编码、BOM 和换行元数据

#### Scenario: 工作区外预览保持只读
- **WHEN** 用户预览显式指定但不属于注册工作区或活动 worktree 的文本文件
- **THEN** 系统继续显示内容但不提供编辑或保存能力

#### Scenario: 不安全文件拒绝编辑
- **WHEN** 文件是二进制、超过 5 MiB、目录、Office/PDF/图片或只能损失性解码
- **THEN** 系统不得进入可写状态，并保持既有只读或错误提示

### Requirement: Markdown 默认使用轻量所见即所得编辑
系统 SHALL 在可写 Markdown 打开后直接显示可编辑的排版内容，而不是先显示预览或用源码框代替所见即所得体验。

#### Scenario: 编辑常用 Markdown 文本
- **WHEN** 用户编辑段落、标题、行内样式、链接文字、引用、代码块、列表、任务列表或已有表格单元格
- **THEN** 系统在排版后的对应位置修改文字，并能序列化成语义等价的 GFM Markdown

#### Scenario: 工具栏保持轻量
- **WHEN** Markdown 编辑器显示格式工具
- **THEN** 工具仅覆盖正文/标题、常用行内样式、列表、引用、代码块和撤销/重做，不显示字体、颜色、对齐、图片或表格结构设计功能

#### Scenario: 复杂 Markdown 保真
- **WHEN** 文档含有图片、Mermaid、数学、原始 HTML、脚注、引用定义或未知扩展
- **THEN** 系统将对应结构显示为不可直接格式编辑的节点，并在保存时保留其原始 Markdown 内容

### Requirement: 文本保存保留磁盘格式并阻止冲突覆盖
系统 MUST 在单文件写锁内重新读取磁盘、比较读取版本，并使用当前文件元数据执行写后验证和失败回滚。

#### Scenario: 无冲突保存
- **WHEN** 用户以匹配当前原始字节的 `read_id` 保存草稿
- **THEN** 系统写入新文本、保持原编码/BOM/换行、回读验证内容并返回新的 `read_id`

#### Scenario: 外部修改导致冲突
- **WHEN** 用户读取后 Agent 或外部程序改变了文件原始字节
- **THEN** 保存接口返回 `HTTP 409`，前端保留草稿且不得覆盖磁盘内容

#### Scenario: 人工保存使 Agent 旧基线失效
- **WHEN** Desktop 用户成功保存文件
- **THEN** 系统清除该文件的 Agent 读取基线和重复读取观察，并使相关 Git 快照失效

### Requirement: 草稿跨预览生命周期保留
系统 SHALL 将文件编辑草稿绑定到预览标签，而不是绑定到当前挂载的内容组件。

#### Scenario: 切换或隐藏后恢复草稿
- **WHEN** 用户在有未保存修改时切换标签、打开浏览器标签或隐藏后重新打开详情面板
- **THEN** 系统恢复同一草稿、光标可继续编辑且磁盘文件尚未被写入

#### Scenario: Agent 刷新不覆盖草稿
- **WHEN** 自动刷新发现 Agent 修改了当前脏文件
- **THEN** 系统保留草稿并显示磁盘可能变化状态，不得用新磁盘文本替换草稿

### Requirement: 编辑操作不依赖按钮并提供明确反馈
系统 SHALL 不显示“编辑”“保存”“取消”按钮，提供 `Ctrl+S` 保存，并在保存进行中、成功、失败和冲突时显示明确状态。

#### Scenario: 保存后继续编辑
- **WHEN** 保存成功
- **THEN** 系统更新基线、移除未保存标记并保持编辑器打开

#### Scenario: 修改后不自动写盘
- **WHEN** 用户修改可写文本但尚未按 `Ctrl+S` 或在关闭确认中选择保存
- **THEN** 系统仅更新页签草稿和未保存标记，不自动写入磁盘
