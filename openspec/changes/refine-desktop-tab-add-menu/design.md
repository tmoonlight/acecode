## 背景

当前预览工作台把加号固定放在标签滚动区右侧。标签较少时，加号与最后一个标签之间会留下大片空白，视觉上不像“新建/打开一个标签”的连续入口；标签较多时，固定在右侧又是合理的，因为用户无需横向滚动即可继续打开内容。

现有加号菜单包含“终端、浏览器、侧边聊天”，但缺少直接打开文件的入口。桌面端已经具备原生文件选择基础设施，文件预览也已经支持将绝对路径规范化后打开为标签，因此本次改动可以复用这两条链路，不引入新的文件读写权限模型。

## 目标与非目标

### 目标

- 标签未发生横向溢出时，加号紧跟在最后一个标签后面。
- 标签发生横向溢出时，加号固定到右侧操作区，始终可见。
- 加号菜单只保留“文件、浏览器、侧边聊天”。
- “文件”通过桌面原生单文件选择框选取文件，初始目录为当前工作区；选中后沿用现有文件预览标签链路打开。
- 取消选择、缺少当前工作区或原生桥接不可用时，不产生错误标签或破坏现有状态。

### 非目标

- 不支持从该入口选择目录或一次选择多个文件。
- 不改变浏览器和侧边聊天入口的既有行为。
- 不改变外部文件只读预览、工作区目录浏览或 Git 操作的授权边界。
- 不重做标签拖动、排序、关闭和滚动条交互。

## 决策

### 1. 依据实际布局溢出状态切换加号位置

复用标签滚动容器的 `scrollWidth` 与 `clientWidth`，并通过现有 `ResizeObserver` 在标签数量、标题宽度、窗口尺寸或缩放变化时重新判断。未溢出时，加号作为标签滚动壳中的紧邻元素；溢出时，加号移到滚动壳外、右侧操作区之前。

选择实际宽度而不是固定标签数量，是因为是否拥挤同时受窗口宽度、标签标题、系统缩放和最小标签宽度影响。两种布局都为同一个 28 像素加号保留空间，以降低临界宽度附近反复切换的风险。

备选方案是按标签数量设置阈值，但同样数量的标签在不同窗口宽度下会得到错误结果，因此不采用。

### 2. 使用专用的桌面单文件选择桥接

在桌面原生层增加单文件选择函数，并暴露独立的 WebView 桥接。桥接只接收当前工作区作为默认目录，只返回取消状态、错误或一个已选择的绝对文件路径，不读取或物化文件内容。

不直接复用编辑器附件选择桥接的返回协议，因为该协议允许多文件和目录，并会为附件准备额外元数据；预览入口只需要一个路径。底层仍复用已有 Windows 文件对话框初始化与默认目录逻辑。

### 3. 复用现有文件预览规范化与标签状态

前端收到绝对路径后调用现有 `openFilePreview`。该函数继续负责将工作区内路径转换为相对路径、将工作区外文件转换为父目录加文件名的只读预览作用域，并通过既有 `openFileTab` 状态机去重和激活标签。

这样不会为菜单入口建立第二套预览、错误处理或外部路径权限规则。

### 4. 菜单项目保持稳定但按能力禁用

菜单顺序固定为“文件、浏览器、侧边聊天”。桌面单文件桥接不可用时，“文件”仍显示但禁用；浏览器入口继续按现有浏览器能力判断。取消原生对话框视为正常无操作，只有真实错误才提示用户。

## 风险与权衡

- **临界宽度布局抖动**：加号在两种位置占用等量宽度，并使用带容差的统一溢出判断；仍需通过组件逻辑测试和实际构建验证。
- **菜单锚点移动**：窗口缩放可能让加号换位。现有菜单会在尺寸变化时关闭，避免浮层停留在旧坐标。
- **平台差异**：当前专用选择器首先沿用现有 Windows 桌面实现；其他平台没有原生实现时菜单项禁用，不影响浏览器和侧边聊天。
- **工作区外文件**：选择器允许用户显式选择任意现有文件；打开后仍走现有外部文件只读预览路径，不放宽目录列举或 Git 边界。

## 迁移计划

该改动不迁移持久化数据。发布后，现有标签状态继续按原格式恢复；加号位置由当前布局即时计算。若需要回滚，只需恢复旧菜单与固定加号布局，桌面桥接没有持久化副作用。
