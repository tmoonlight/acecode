## 为什么

Desktop 详情标签栏的“+”目前始终占据右侧固定控制区，标签很少时会与最后一个标签分离，削弱了“在此处新增”的空间关系；同时菜单仍提供“终端”且缺少直接选择文件的入口。需要让入口位置随标签是否溢出而变化，并把菜单收敛到用户当前需要的三项操作。

## 变更内容

- 当详情标签未占满可用宽度时，将“+”紧跟在最后一个标签后；只有标签发生溢出时，才把“+”拼接到右侧固定控制区，保证始终可见。
- 将“+”菜单固定精简为“文件”“浏览器”“侧边聊天”，移除“终端”。
- 选择“文件”时打开桌面原生文件选择对话框，默认定位到当前工作区，并将选中的单个文件作为详情标签打开。
- 用户取消选择、当前会话没有工作区或原生文件对话框不可用时，以安全、可恢复的方式处理，不影响既有标签。

## 能力

### 新能力

- 无。

### 修改能力

- `preview-tab-workbench`：修改详情标签栏加号的位置规则、菜单内容及“文件”入口行为。

## 影响

- WebUI：详情标签栏布局、溢出检测、加号菜单、文件打开动作及相关组件测试。
- Desktop 原生壳：文件选择对话框桥接，以及默认目录和单文件结果的传递。
- 既有行为：浏览器与侧边聊天入口保持原路径；终端不再出现在该菜单中。
