## 背景

当前 `SearchPalette` 打开后调用 `listAllWorkspaceSessions()`，而 `/api/session-search/sessions` 会在请求线程内执行 `build_global_session_catalog()`：枚举 `projects` 下所有一级目录、读取每个 `*.meta.json`、合并活跃会话，再复用完整 session JSON 序列化。空查询最终只显示 50 条，却必须先等待约 1.6 万条会话全部扫描、序列化和传输。本机该路径稳定需要 43–47 秒，超过通用 30 秒 HTTP 超时。

正文搜索同样会遍历全局项目集合，并可能在请求期间补建旧项目索引。浏览器 `AbortController` 只能停止等待响应；现有服务端没有请求身份或取消令牌，客户端断开后扫描仍会继续。

约束如下：

- 所有有效、未归档、非后台子代理会话仍必须可搜索，工作区可见性不是范围边界。
- 不能把完整 transcript 或第二份用户消息正文数据库引入全局目录。
- Desktop、Web 和 remote-control 仍共享同一会话身份与过滤语义。
- 搜索关闭后，因该搜索而进行的目录/正文扫描必须尽快停止；后续重新打开应从已完成的缓存分片继续，而不是清空重来。

## 目标 / 非目标

**目标：**

- 搜索弹层打开后立即获得已就绪的小批结果，不等待全局预热完成。
- 目录元数据只在启动预热、明确失效或发现新项目时读取；普通搜索请求只查询内存快照。
- 元数据结果与正文结果均分批推进、可报告进度、可稳定分页，并能由同一个请求 id 取消。
- 关闭、Escape、点击遮罩、查询替换和组件卸载都执行端到端取消。
- 搜索接口只传输展示、匹配与跳转所需字段。

**非目标：**

- 不删除历史项目目录或会话，也不把搜索重新限制到当前/可见工作区。
- 不修改 JSONL、`SessionMeta` 或现有 per-project SQLite 用户消息索引格式。
- 不引入全文分词、OCR、assistant/tool 消息搜索或新的第三方数据库。
- 不让 remote-control 依赖 Web 搜索请求生命周期；它可继续使用同步目录构建器，后续再单独迁移到共享快照。

## 技术决策

### 决策 1：使用进程内、按项目分片的增量目录快照

新增 `GlobalSessionCatalogIndex`，由 WebServer `Impl` 持有。索引启动时只枚举并排序一级项目路径，然后由单个后台 worker 逐项目调用元数据扫描，将每个项目的不可变结果分片提交到共享快照。快照记录 `scanned_projects`、`total_projects`、`complete` 和单调递增 `generation`。

索引在 daemon 启动后立即低优先级预热。首个搜索请求携带 `request_id` 并附着到索引，允许 worker 继续推进；显式取消最后一个附着请求后，worker 在当前元数据文件/项目边界暂停。下次请求从未完成位置继续。这样关闭搜索不会让一次 45 秒扫描继续跑完，同时保留已完成分片。

索引提供 `invalidate_project(hash)`：会话归档、删除、恢复、重命名及 workspace 元数据变化后只把对应分片放入脏队列。活跃会话在每次查询时从 `SessionClient::list_sessions()` 合并，因此尚未落盘的创建/状态变化不必等待磁盘分片刷新。后台完成一轮后以低频目录签名检查发现外部/TUI 写入和新项目。

元数据读取新增可选取消检查，在遍历文件时观察停止令牌，避免一个含上千 meta 的项目成为不可中断的长临界区。

备选方案是每次请求继续全扫但增加 worker。它仍与数据量线性阻塞、不能可靠取消，也会重复文件 I/O，因此不采用。另一个方案是持久化一份全局数据库；它增加迁移与清理边界，本轮先使用可重建的内存分片。

### 决策 2：元数据查询改为精简、服务端过滤和有界分页

`GET /api/session-search/sessions` 接受：

- `request_id`：客户端生成的稳定搜索实例 id；
- `q`：可为空的元数据查询；
- `limit`：默认 50，服务端限定最大值；
- `cursor`：只在完整快照的同一 generation 内继续分页的 opaque cursor。

响应只包含 `id`、`workspace_hash`、`workspaceName`、`workspace_cwd`、`workspace_visible`、`no_workspace`、`title`、`title_source`、`summary`、`created_at`、`updated_at`、`active` 和 `busy` 等展示/跳转字段。服务端对已扫描分片和活跃会话执行与当前前端一致的标题、摘要、工作区和新鲜度排序；空查询返回最近 50 条。响应附带 `progress`、有界局部错误和可选 `next_cursor`。

快照尚未完成时，客户端按 generation/progress 轮询并替换当前 top-N，不使用分页 cursor；完整后才允许稳定翻页。这样部分结果可以立即显示，同时不会把暂时的扫描顺序伪装成最终分页顺序。

备选方案是继续把全部会话发给浏览器后过滤。它产生约 16 MB 响应并迫使 WebView 排序全部记录，违背有界返回目标，因此不采用。

### 决策 3：正文搜索使用服务端请求作业和时间片推进

正文搜索沿用 per-project `SessionUserMessageIndex`，但不再在一个 HTTP handler 中遍历全部项目。`request_id + normalized query` 标识一个服务端作业；每次 `GET /api/session-search/user-messages` 只推进固定项目上限和时间预算，累计全局最佳命中并返回当前 top-N、处理进度和 `complete`。

作业保存启动时已发现的项目路径，并在目录 generation 变化时只追加新发现路径；已处理游标不回退。索引补建和 session 遍历接收同一取消检查；到达时间片、项目上限或取消后立即返回/停止。查询变化先取消旧作业，再创建新作业。取消或超时闲置的作业会从注册表清理。

备选方案是为每次键入启动一个长后台线程。快速输入会堆积线程和磁盘扫描，取消竞争也更难验证，因此采用由短 HTTP 批次推进的作业。

### 决策 4：显式取消协议与浏览器中止同时执行

新增幂等端点 `POST /api/session-search/requests/<request_id>/cancel`。它同时标记元数据附着请求和正文作业取消。前端为一次面板查询周期持有一个 `AbortController`：输入变化、关闭按钮、Escape、点击遮罩或卸载时先 `abort()` 当前 fetch，再用独立的短请求（支持 `keepalive` 时启用）通知取消端点。

服务端取消令牌在项目之间、meta 文件之间、正文索引 session 之间检查。取消响应不得作为错误提示，也不得写入成功缓存；真实超时和服务端错误保留可见重试入口。

仅依赖 TCP 断开不可移植且 Crow handler 没有稳定的断开回调，因此显式取消是权威路径，浏览器 abort 负责立即释放 UI 等待。

### 决策 5：前端渐进显示而不是全局 loading 门

SearchPalette 打开后立即渲染输入框、当前已缓存结果和进度行。元数据批次到达即替换 top-N；正文批次到达即合并匹配。未完成时显示“正在索引 x/y”，但输入、关闭和已有结果始终可操作。完整结果超过当前页时显示有界的“加载更多”。

模块缓存只保留当前 daemon 连接的空查询最近结果；session-list 事件使其失效，但不清空正在显示的最后一份结果。查询结果始终由对应 `request_id` 隔离，取消不会把空数组覆盖到最近成功结果。

## 风险 / 权衡

- [风险] 启动预热与用户其它磁盘工作竞争。→ 单 worker、小批提交、可暂停，并让附着搜索控制是否继续高优先级推进。
- [风险] 快照预热未完成时暂时看不到尚未扫描目录的命中。→ 明确显示进度、自动拉取短批次，完成前不宣称结果完整。
- [风险] generation 变化使分页 cursor 失效。→ 返回明确的 cursor 失效响应，前端保留当前展示并从第一页轻量刷新。
- [风险] 外部进程直接修改 meta 而未触发生命周期通知。→ 完成后低频检查项目目录签名，新目录和变更分片增量入队。
- [风险] 显式取消请求本身因窗口关闭失败。→ 先本地 abort；服务端作业还受短批次、闲置 TTL 和取消检查约束，不会退化成无界扫描。
- [风险] 目录快照占用内存。→ 分片只保留 `SessionMeta` 搜索字段和工作区属性，不保留 transcript、完整 tool/todo/token 数据。

## 迁移方案

1. 保留现有同步 `build_global_session_catalog()` 供非 Web 调用，新增索引服务并只切换 Web 搜索路由。
2. 新接口字段向后兼容地保留 `sessions`、`errors` 和 `matches` 顶层数组；旧前端可读取首批结果，但不会使用进度与分页。
3. 前端切换到 request id、渐进轮询和取消后，再移除全量 catalog 的调用假设与 60 秒全量缓存。
4. 回滚时恢复旧路由构建器即可；无持久化 schema 或数据迁移需要撤销。

## 待确认问题

无。默认元数据页大小为 50；正文每批使用小项目上限与短时间预算，具体数值由性能测试确定并保持服务端上限。
