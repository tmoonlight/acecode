## 为什么要做

全局任务搜索在首次打开时同步枚举全部项目目录并返回所有会话；本机约 1.6 万条会话时单次请求需要 43–47 秒、响应约 16 MB，超过前端 30 秒超时，导致搜索无法随开随用，也无法在关闭面板后及时停止后台扫描。

## 变更内容

- 建立 daemon 内共享的全局会话目录快照：后台分批预热，按项目目录增量刷新，并在会话生命周期事件后精确失效，而不是每次打开搜索都全盘重扫。
- 将全局搜索接口改为服务端查询、稳定分页和有界批次返回；空查询只取最近少量会话，有查询时仍覆盖全部持久化及活跃普通会话。
- 为搜索提供独立的精简结果模型，只返回匹配、展示、分页和跳转所需字段，不再复用完整会话序列化。
- 为每次搜索分配可取消请求；输入变化、关闭按钮、Escape、点击遮罩或组件卸载都会中止浏览器请求，服务端在项目批次之间观察断开/取消并停止剩余工作。
- 搜索面板先展示已就绪的小批结果，再按需加载后续批次；预热尚未完成时返回进度和可继续游标，不用一个长请求阻塞界面。
- 对超时、局部扫描失败和取消使用不同状态：取消保持安静且不污染缓存，真实失败提供可见重试信息。

## 能力

### 新增能力

- `incremental-global-session-search`：定义全局会话目录的增量快照、有界分页、精简结果、渐进加载和端到端取消契约。

### 修改能力

无。

## 影响范围

- 会话层：`src/session/global_session_catalog.*` 及新增的目录快照/查询协作逻辑。
- Daemon Web API：`GET /api/session-search/sessions` 的查询、limit、cursor、进度和取消语义，以及用户消息正文搜索的共享目录范围。
- Web 前端：`web/src/lib/api.js`、`SearchPalette.jsx`、搜索排序/合并逻辑和缓存失效策略。
- 生命周期集成：会话创建、更新、归档、删除与 workspace 元数据变化需要通知目录快照增量刷新。
- 测试与文档：目录快照、分页稳定性、精简响应、请求取消、关闭面板停止搜索及大规模性能回归测试；更新 `docs/daemon-api.md`。
- 不新增第三方依赖，不改变会话 JSONL/meta 格式，也不缩小“搜索所有普通未归档会话”的范围。
