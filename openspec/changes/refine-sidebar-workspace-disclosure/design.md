## Context

动机见 proposal.md。`WorkspaceGroup` 的行点击根据 `ws.active` 选择折叠或激活，激活会进入首页；会话列表以 Set 表示全部展开。已有手动收起保护、定位当前会话和后台全量缓存逻辑必须保持协作。

## Goals / Non-Goals

目标是将文件夹 disclosure 与导航分离，用每列表的可见数量表达分批展开。沿用当前字体、间距和颜色 token。不修改后端分页协议、显式工作区导航请求或桌面菜单动作。

## Decisions

- 文件夹行统一调用已有 `onToggle`；删除依赖 `ws.active` 的视觉分支。保留工作区运行身份元数据和新建按钮的事件隔离。
- `expandedSessionLists` 使用 Map 保存可见数量，缺省为五条，展开每次加五；全部展示后点击折叠删除该键。用单一计数源替代 boolean 与额外分页状态并存。
- 延续现有后台加载完整列表的缓存策略，渲染始终受可见数量约束。点击时更新计数，异步响应只更新数据，避免响应覆盖后续收起操作。
- 部分列表首次补齐完整历史时，将新读取的历史会话追加到现有顺序后，再进行常规元数据合并；避免历史记录被当作新建会话提升到顶部。普通刷新与真正的会话创建事件保留原有排序策略。
- 手动增量展开也设置自动揭示抑制，防止当前会话在后面的批次导致一次点击跳过多批。新的会话导航清除抑制，自动揭示仅增加到目标所在批次。
- 揭示索引使用与渲染一致的非置顶列表；完整加载后用非置顶会话数判断是否到末尾，防止置顶或不精确 total 造成无限“展开显示”。
- 首批后台请求在五条基础上补偿已知置顶数量，确保过滤后仍能显示五条普通会话；这复用既有 limit 参数。
- 两类列表的展开/折叠按钮都仅保留 `hover:text-fg` 和颜色过渡。

## Risks / Trade-offs

- 缓存加载期间用户继续点击可能累积多次五条请求；这是每次点击递增的语义，数据返回后仅展示累计数量。
- 保留全量缓存加载意味着此次只改变展示数量；后端分页与缓存优化不在本次范围。
- 现有未提交的 Sidebar 会话 hover 缓存改动通过修改前快照核对并保留。
