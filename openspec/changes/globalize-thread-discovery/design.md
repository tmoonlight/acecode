## Context

`ThreadService::list` 当前仅扫描调用方项目，公共解析函数也按调用方 cwd 过滤活跃会话和磁盘目标。现有全局会话目录已处理隐藏项目、未注册项目和无工作区会话，但默认排除归档及子代理，会话工具原本允许列出子代理。

## Goals / Non-Goals

目标是复用已有目录合并与元数据读取能力，使查询工具可以访问完整 ACECode 数据范围，并保持结果有界。此次不扩大创建、续聊、重命名、置顶、归档、删除及修复的操作范围，不改动界面搜索行为。

## Decisions

1. 全局目录增加默认关闭的归档、子代理包含选项。工具列举包含子代理，并按 `includeArchived` 决定归档过滤；现有界面调用继续使用默认选项。
2. `list_threads` 保留全部置顶结果，每个项目内部按已持久化 pin 顺序排列，项目之间按 hash 排序。普通会话按更新时间排序，`limit` 仍限制每页条数，通过 `cursor` / `nextCursor` 续读。工作区作为 `workspaceHash`、`cwd`、`noWorkspace` 等返回属性。
3. 为读取及等待提供独立的全局只读定位入口，按目标 ID 读取精确元数据路径，不为单个目标重读全库 transcript。可选 `workspaceHash` 直接定位存储项目，消除跨项目同 ID 歧义。调用方及活跃目标复用已有 manager，不创建 writer。
4. 保留现有写工具的当前工作区解析函数，避免改变与本次会话查找无关的操作语义。
5. 测试使用临时用户数据目录，覆盖跨项目持久化与活跃会话、空调用 cwd、归档、子代理、无工作区、置顶分页及歧义定位，避免读取真实用户会话。

## Risks / Trade-offs

- 全局列举会访问更多元数据 → 复用有界并发目录扫描，不读取 transcript 回填摘要；单目标查询有 workspaceHash 时直接定位。
- 列表翻页期间会话发生变化 → cursor 表示当前排序结果的偏移，保持与现有 turn 分页一致的简单语义，不承诺跨调用冻结快照。
- 扫描部分项目失败 → 返回错误摘要，不把不完整扫描伪装成完整空结果。
- 同 ID 误读 → 未明确 workspaceHash 且磁盘存在多个匹配时返回歧义错误。
