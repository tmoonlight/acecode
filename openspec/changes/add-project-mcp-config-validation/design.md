## Context

daemon 会话共享 `McpManager` 与 `ToolExecutor`。现有公共配置支持原子写入和完整文档恢复，但 MCP 的启动、HTTP 和 TUI 解析各自独立。用户提供 https://modelcontextprotocol.io/specification/2026-07-28/schema 并已确认本次使用 ACECode 配置 Schema。

## Goals / Non-Goals

**目标：** 统一 Schema，按范围保存与恢复有效配置，写入失败不发布候选状态，在共享 daemon 中隔离项目工具。

**非目标：** 升级 MCP 协议、OAuth 或拦截外部程序写文件。外部修改在加载、启动前校验。

## Decisions

1. 项目文件为 `<project>/.acecode/mcp.json`，使用 `{ "mcp_servers": { ... } }`。从工作目录向上查找，以最近 Git 仓库/worktree 为边界，复用项目目录工具并在用户主目录前停止；没有已有文件则使用 Git 根目录，没有 Git 根目录则使用工作目录。
2. `AppConfig.mcp_servers` 只保存公共配置。项目覆盖独立解析，规范化项目路径生成内部 owner；能力策略将可见名称映射到确切 owner，disabled 项目条目也不得回退到同名公共服务器。
3. 内置离线配置 Schema，集中校验其使用的关键词。先校验原始 JSON，再构造 C++ 结构，避免转换和忽略字段掩盖错误。API 与诊断返回同一规则。Windows 的带边界正则使用完整匹配，拒绝字段中的嵌入或结尾换行。
4. 每个文件保存受保护的 `.mcp-last-good` 快照，恢复前重新校验。公共恢复仅替换 MCP 段，项目恢复专用文件；归档无效原文，不允许部分成功加载。
5. 持久化成功后再发布 AppConfig 和运行时。快照保存失败须撤销活动文件变更。读取时隐藏的认证字段在省略时保留，空字符串显式清除。通用配置保存、受管理文本编辑经过相同校验。
6. 设置选择公共或已登记项目，API 默认仍为公共。按 owner 调整注册项，经会话串行控制入口刷新能力策略，以单调递增 generation 丢弃过期异步连接结果。
7. 显式专家选择允许使用默认禁用的服务器。保留其连接时，运行时仍保存真实的 disabled 定义，后续刷新不应重复拆除连接。
8. `/mcp` 命令保持运行时控制语义，按当前项目解析名称；持久化编辑由设置和管理界面完成。

## Risks / Trade-offs

- 原先被忽略的字段错误现在被拒绝；保留已废弃 TLS 字段的类型兼容并继续忽略。
- 快照可能包含认证信息，沿用受保护写入，诊断不回显字段值。
- 无有效快照时报告 Schema 错误，不猜测配置。
- 测试须显式建立独立 Git 边界，避免用户主目录属于 Git 仓库时修改真实配置。
- Windows 正则行为与其他平台不同，保留换行、NUL 等回归用例。

## Migration Plan

公共配置不搬迁，首次有效加载建立 MCP 快照；已有完整配置备份重新验证后可用于首次恢复。项目通过独立文件或设置界面启用。回退软件版本仍可读取公共配置，项目文件保持独立。
