## Purpose

定义会话历史发送给模型时工具调用的身份与配对约定，确保兼容服务跨响应复用调用 ID 时仍能保留每次真实工具结果，并在重复投影、历史恢复和不同提供者之间保持确定性与完整性。

## ADDED Requirements

### Requirement: 跨响应复用调用 ID 保留完整工具结果

系统 SHALL 保留不同 assistant 消息中的有效工具调用及其结果，即使它们复用相同 ID。提供者请求中的有效调用 ID MUST 全局唯一，冲突调用及其匹配结果 MUST 使用同一新 ID。

#### Scenario: 连续工具步骤复用 ID
- **WHEN** 截图调用及下一条 assistant 的视觉分析调用均使用 `call_0` 并各有成功结果
- **THEN** 请求保留两组调用及结果，第二组使用不同 ID，末条仍是视觉分析工具结果

#### Scenario: 用户继续后再次复用 ID
- **WHEN** 用户发送新消息后又产生同 ID 工具调用
- **THEN** 系统保留新调用和对应输出，不重用之前调用的结果

#### Scenario: 同一响应内重复条目
- **WHEN** 单条 assistant 的工具调用数组内存在重复 ID，结果块也包含重复结果
- **THEN** 仅保留该数组内首个有效调用和结果块的首个匹配结果

#### Scenario: 中断调用之后复用 ID
- **WHEN** 较早或较晚的复用 ID 调用缺失结果
- **THEN** 仅为缺失结果的那次调用生成 outcome unknown 占位，真实结果仍匹配所属调用

### Requirement: 历史投影保持稳定且不修改原始记录

系统 SHALL 确定性地解决调用 ID 冲突，生成 ID MUST 避开整个输入中的原始调用与结果 ID。对已修复历史再次投影 MUST 保持逐字段相同，原始内存消息和磁盘会话 MUST 不被改写。

#### Scenario: 候选 ID 与后续原始 ID 重名
- **WHEN** 输入包含与重映射候选 ID 相同的较晚调用或无关联结果
- **THEN** 生成另一个无冲突 ID，不误关联结果或修改原本唯一的调用

#### Scenario: 多次投影与多提供者序列化
- **WHEN** 相同历史多次经过请求准备与提供者构造
- **THEN** 修复结果稳定，OpenAI 的 tool_call_id 与 Anthropic 的 tool_use_id 分别保持对应关系，原始消息保留原 ID、内容、附件与元数据
