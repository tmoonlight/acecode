## Context

会话 ID 当前由 SessionStorage 生成 `YYYYMMDD-HHMMSS-xxxx`，部分诊断使用固定正则；日志由 Logger 和输入跟踪独立生成，反馈收集按连字符前缀匹配。多个持久化配置、IPC 文件和数据目录也带连字符。

## Goals / Non-Goals

目标是统一自动生成名称，并保证旧名称可用。保留用户输入路径、现有会话 ID、协议 UUID 和第三方要求的文件名；不通过全局替换路径或重写数据完成迁移。

## Decisions

1. 在 base/utils 提供共享名称转换和持久化路径兼容工具。转换仅用于系统负责生成的新名称，兼容路径优先使用实际存在的旧资源，避免创建并行空数据库或丢失配置。
2. 新会话 ID 使用下划线；读取时保持 ID 原样，不把旧 ID 转换成另一个身份。旧 PID 后缀实验数据仍按原约定排除，新格式同样不能误列为独立会话。
3. 日志新写使用下划线；反馈发现识别两种前缀并按真实修改时间选择，不依靠文件名字典序推断最新记录。
4. 新反馈包、导出建议名、工具结果和临时文件在生成边界规范化；历史元数据存储的文件路径直接按记录读取。
5. 固定名称的持久化资源首次创建使用新名，已有旧资源继续使用旧路径。协议 / 单实例协调资源的修改必须覆盖生产者、消费者及开发启动器，避免同时出现两个资源所有者。

## Risks / Trade-offs

旧程序未必识别新会话 ID；本次保证新版读取旧数据，不承诺旧程序理解未来全部新增数据。新旧路径并存时不得删除其中一个；必须给出确定的优先级并验证历史读取。SQLite 自身生成的 `-wal`、`-shm` 属于第三方协议，不改写。

## Validation Strategy

覆盖新名称无连字符、新旧会话混合列表与恢复、旧 PID 后缀排除、跨日和多进程日志追加、反馈新旧日志发现、旧配置与备份读取，以及实际构建。按改动范围运行定向原生与脚本测试、静态分层闸门和严格 OpenSpec 验证。

## 生成入口清单

完整名称对照及兼容例外记录在 `docs/runtime_file_naming.md`。实现覆盖会话/诊断、Logger/FTXUI、反馈、配置恢复、工具输出/截图、Web 粘贴与导出、升级临时文件、记忆观察/归档、数据库/运行记录、浏览器配置和开发启动器。共享进程锁、标准协议资源与用户命名保持原约定。
