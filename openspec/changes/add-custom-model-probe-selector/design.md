## 背景（Context）

`ProviderCatalogPicker.jsx` 已为目录型和受管 Provider 提供真实模型探测，并通过 `apiClient.probeModels` 调用 Daemon 的 `POST /api/models/probe`。自定义 OpenAI 兼容 Provider 使用 `model_input=manual` 分支，只显示直接绑定草稿的 `Model ID` 文本框，因此同一条探测能力在截图所示位置不可用。

新增模型模式已经支持用逗号分隔的多个模型 ID，并由 `buildModelMutationPayloads` 为每个 ID 生成独立预设。本变更只补齐自定义兼容 Provider 的探测选择交互，不改变保存合同。

## 目标 / 非目标（Goals / Non-Goals）

**目标：**

- 在 `Model ID` 标题行右侧提供符合现有视觉规范的“探测模型”按钮。
- 使用独立、可访问、支持搜索和多选的选择弹窗呈现真实探测结果。
- 让选择过程具有事务性：探测、勾选和取消均不修改主表单，只有有效确认才一次性回填。
- 保留直接输入、现有 API Key/请求头处理、批量保存和错误脱敏行为。

**非目标：**

- 不新增或修改 Daemon API、Provider 协议和模型目录数据。
- 不自动探测，也不要求用户必须通过探测才能保存。
- 不改变目录型、受管 Provider 的现有内嵌模型列表。
- 不允许编辑单个已有预设时保存多个模型；编辑模式的选择弹窗保持单选。

## 设计决策（Decisions）

### 1. 复用现有探测链路，只增加聚焦弹窗

按钮继续使用当前草稿的运行时 Provider、Base URL、API Key 和经过校验的自定义请求头调用 `apiClient.probeModels`，并复用 `normalizeModelProbeResult` 与错误脱敏。Base URL 为空或请求进行中时按钮禁用。

新增 `ModelProbeDialog` 聚焦组件负责搜索、加载/错误/空状态、复选列表和确认按钮；`ProviderCatalogPicker` 负责请求与草稿回填。相比把第二套长列表直接塞进手工输入分支，独立组件能保持右侧详情简洁，并明确嵌套弹窗的焦点层级。

### 2. 选择弹窗采用严格的显式关闭边界

选择弹窗复用共享 `Modal`，但设置 `dismissOnBackdrop={false}` 与 `dismissOnEscape={false}`，并使用高于主模型弹窗的层级。右上角叉号是唯一取消入口；取消只卸载选择弹窗，不修改主草稿。

确认按钮在没有选中模型、仍在加载或探测失败时禁用。至少选中一个模型后，用户点击“添加所选模型”才把结果写入主草稿并关闭。模型行本身只切换选择状态，不自动关闭，以保证多选可完成。

### 3. 确认时替换当前模型选择，并保留表单其他字段

打开弹窗后，探测结果中与当前 `draft.model` 匹配的 ID 初始选中；未出现在探测结果中的手工 ID不会被隐藏地带入选择状态。只有用户确认时，所选 ID 才按探测结果顺序写回逗号分隔的 `draft.model`，并记录可用的上下文窗口元数据。

回填必须保留 Base URL、API Key、请求头、可选预设名称和高级覆盖。若预设名称为空，回填过程仍保持为空，使现有自定义兼容保存逻辑继续为每个模型精确使用 Model ID 作为名称。

新增模式使用复选框并允许多选；编辑模式使用单选按钮，从而继续满足 `MULTI_MODEL_EDIT` 约束。直接 `Model ID` 输入框始终保留，用户可在确认后继续编辑或清空。

### 4. 样式与可访问性沿用 ACECode 语义 token

按钮、列表、状态、输入框和页脚只使用 `bg-surface`、`bg-surface-alt`、`border-border`、`text-fg-*`、`accent`、`danger` 等现有 token。弹窗具有标题关联、焦点圈、`aria-busy`、复选/单选语义、已选数量和具名关闭按钮；普通模型 ID 继续使用 sans 字体。

## 风险 / 权衡（Risks / Trade-offs）

- [嵌套弹窗可能让 Escape 误关主表单] → 选择弹窗保持最上层并禁用 Escape 关闭，共享 `Modal` 的最上层检测阻止事件落到父弹窗。
- [探测请求较慢或失败] → 弹窗立即出现并展示加载/错误状态，叉号始终可取消，主表单和手工输入不受影响。
- [探测结果不包含手工模型 ID] → 只有明确确认才替换模型字段；用户取消时原值完整保留，确认后仍可直接编辑。
- [多模型名称被首个结果意外改写] → 回填显式保留原预设名称，空名称继续由现有批量 payload 逻辑按各自 Model ID 生成。

## 迁移计划（Migration Plan）

1. 增加选择弹窗组件和 Provider 选择器编排逻辑。
2. 增加纯辅助逻辑与结构回归测试，运行 Web 聚焦测试和生产构建。
3. 不迁移配置或服务端数据；回滚时移除新增组件和入口即可，现有手工模型 ID 与 API 合同仍兼容。
