# ACECode 专家组件高保真设计需求

状态：高保真设计已导入，已批准进入实现
用途：作为专家相关界面、交互、数据模型与运行时能力约束的实现和验收基线
实施说明：2026-07-25 用户已明确要求结合导入设计稿调整所有专家相关界面，因此本次实施会接入生产代码并按需扩展后端协议；本说明覆盖此前“只做设计”的阶段限制。

## 1. 核心目标

为 ACECode 设计一套完整的“专家 / 专家团”使用与管理体验，覆盖两个相互独立的界面：

1. **真实对话页面中的专家选择入口**：放在现有聊天框的“+”菜单内。
2. **专家组件页面**：用于浏览、筛选、查看和编辑专家与专家团。

这两个界面不能混在一起。

> 关键纠正：专家组件页面底部不允许出现模拟聊天框、悬浮聊天框、对话状态栏或任何聊天输入框。聊天框菜单只能画在真实对话页面的上下文中，或者作为独立组件稿展示。

## 2. 术语与数据含义

| 名称 | 含义 | 设计要求 |
|---|---|---|
| 专家 | 可被派遣到当前对话的单个专家角色 | 可拥有多个 Tag |
| 专家团 | 由多位专家组成的协作组合 | 有成员和一位主理人 |
| Tag | 专家的多选标签，例如产品、开发、运营 | 不是互斥 Category；同一专家可出现在多个 Tag 下 |
| 擅长领域 | 专家能解决的能力主题 | 展示在专家卡片上 |
| 开场白 | 用户可快捷选用的问题或任务模板 | 不展示在专家卡片上，只在详情中展示 |
| 派遣 | 将专家或专家团应用到当前对话 | 所有使用按钮统一写“派遣” |

示例：吴八哥可以同时拥有“OPC-一人公司”和“开发”两个 Tag，因此会同时出现在这两个 Tag 的筛选结果中。

## 4. A 界面：真实对话聊天框中的“+”菜单

### 4.1 一级菜单

沿用 ACECode 所有对话页面已经存在的聊天框，不创建第二套聊天框。

```text
真实对话页面

┌────────────────────────────────────────────────────────┐
│ 当前对话内容                                           │
│                                                        │
└────────────────────────────────────────────────────────┘

                 ┌───────────────────┐
                 │ 专家组件        > │
                 ├───────────────────┤
                 │ 文件或文件夹      │
                 └───────────────────┘
┌────┬───────────────────────────────────────────┬───────┐
│ +  │ 输入消息                                  │ 发送  │
└────┴───────────────────────────────────────────┴───────┘
```

一级菜单的顺序和文案必须为：

1. `专家组件`，带 SVG 图标和二级菜单箭头。
2. 分割线。
3. `文件或文件夹`。

明确移除原来的“浏览器”选项。

### 4.2 专家组件二级菜单

```text
┌───────────────────┐  ┌──────────────────────────────────────────────┐
│ 专家组件        > │  │ [头像] 高级开发工程师   高级开发 / 架构设计 │
├───────────────────┤  │ [头像] 产品交付专家团   需求拆解 / 体验验收 │
│ 文件或文件夹      │  │ [头像] 内容创作专家     内容策略 / 品牌叙事 │
└───────────────────┘  │ [头像] 发布质量专家团   审查 / 测试 / 发布  │
                       │ [头像] UI 设计师         UI / 组件库 / 规范  │
                       ├──────────────────────────────────────────────┤
                       │ [SVG] 更多专家                              │
                       └──────────────────────────────────────────────┘
```

要求：

- 专家和专家团混排在同一份最近使用记录中。
- 最多显示最近使用的 5 个组件。
- 最近项必须使用**单行布局**，不能做成“名称一行、介绍一行”的双行 item。
- 单行结构建议为：头像、名称、擅长领域摘要、可选的“专家 / 专家团”弱标签。
- 名称和擅长领域过长时单行省略，不得撑高 item。
- 最后一项固定为带 SVG 图标的 `更多专家`。
- 有最近记录时，在最近列表和“更多专家”之间显示分割线。

无最近记录时：

```text
┌────────────────────────┐
│ [SVG] 更多专家         │
└────────────────────────┘
```

- 只显示“更多专家”。
- 不显示“没有最近的专家”。
- 不显示空状态插画、提示语或占位行。
- 没有最近项时也不保留多余分割线。

### 4.3 派遣行为

- 所有对话的聊天框都能选择专家和专家团。
- 点击最近项即派遣到**当前对话**。
- 派遣后不切换页面、不新建对话、不跳转到专家组件页面。
- 当前选择显示在对话现有的专家状态区域或状态胶囊中。
- 当前专家或专家团状态旁统一提供 `×`。新任务中点击后清除待绑定专家；已有会话中点击后只清除持久化/UI 绑定，不重建 AgentLoop 上下文，不使 KV cache 失效。
- 用户聊到一半也可以切换专家或专家团。
- 切换只影响后续对话，不应改写已经发送的消息。
- 如果当前有一轮正在执行，设计上应表达“下一轮开始使用新专家”，不能让用户误以为正在执行的一轮被强行替换。
- 最近使用记录在各个对话聊天框之间共享；再次使用的组件移到第一位，按 ID 去重并始终截断为 5 个。

点击 `更多专家`：

- 打开专家选择界面或专家组件页面。
- 如果产品采用弹窗选择器，应保留当前对话上下文。
- 完成选择后回到原对话并更新专家状态。
- 不能因为选择专家而丢失聊天框中尚未发送的草稿。

## 5. B 界面：专家组件页面

### 5.1 页面级布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 扩展 / 专家组件                                      新建专家   │
│ 按工作领域找到合适的专家，查看能力后派遣到当前对话               │
├──────────────────────────────────────────────────────────────────┤
│ 专家   专家团                      [搜索]   最近使用 / 最近创建  │
├──────────────────────────────────────────────────────────────────┤
│ 全部  OPC-一人公司  产品运营  开发  设计  数据智能  营销增长 ... │
├──────────────────────────────────────────────────────────────────┤
│ 10 个可用组件                             同一专家可有多个 Tag   │
├──────────────────────────────────────────────────────────────────┤
│ [专家卡片]  [专家卡片]  [专家卡片]  [专家卡片]                  │
│ [专家卡片]  [专家卡片]  [专家卡片]  [专家卡片]                  │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

页面到此结束。
底部不允许追加聊天框、对话状态栏或悬浮输入区域。
```

### 5.2 页签层级

一级页签：

- `专家`
- `专家团`

二级页签：

- 二级页签是 Tag，不是 Category。
- 默认包含 `全部`。
- 其他示例：`OPC-一人公司`、`产品运营`、`开发`、`设计`、`数据智能`、`营销增长`、`内容创作`、`销售商务`、`运营人力`、`项目质量`、`法务安全`、`行业顾问`。
- 根据当前一级页签实际存在的 Tag 动态显示。
- Tag 较多时允许横向滚动，不换成下拉框。

搜索：

- 搜索专家名称、作者、能力介绍、Tag 和擅长领域。
- 开场白不作为卡片展示内容，但可以纳入搜索索引。

排序：

- 至少支持最近使用和最近创建。
- 如果设计采用“最热 / 最新”，应明确映射到真实排序含义，不能只做装饰。

### 5.3 专家卡片

卡片内容：

1. 头像。
2. 专家名称。
3. 作者或专家称呼。
4. `派遣`按钮。
5. 一段简短能力介绍。
6. 专家类型与 Tag。
7. `擅长领域`及 2～3 个领域标签。

卡片不得展示：

- 开场白。
- Skill、MCP 或本地工具的完整配置。
- 冗长的双层介绍。

擅长领域与开场白必须严格区分：

| 内容 | 卡片 | 详情弹窗 | 编辑器 |
|---|---:|---:|---:|
| 能力介绍 | 是 | 是 | 是 |
| 擅长领域 | 是 | 是 | 是，每行一个 |
| 开场白 | 否 | 是，可点击 | 是，每行一个 |

`派遣`按钮在桌面端可以悬停显示，但键盘聚焦和触屏设备上必须可见。

### 5.4 专家团卡片

专家团卡片沿用专家卡片的视觉结构，但需要明确展示：

- 专家团名称。
- 主理人。
- 成员数量。
- 专家团 Tag。
- 团队擅长领域。
- `派遣`按钮。

不能把专家团伪装成普通专家；类型信息必须可辨认，但不要使用过重的大标签。

│ [头像] 专家名称                         编辑          ×  │
│        作者  [专家] [Tag] [Tag]                         │
├──────────────────────────────────────────────────────────┤
│ 能力介绍                                                 │
│ 一段简短介绍                                             │
│                                                          │

│ [领域 A] [领域 B] [领域 C]                              │
│                                                          │
│ 试试这样问我                          选择后填入聊天框   │
│ > 开场白 1                                               │
│ > 开场白 2                                               │

├──────────────────────────────────────────────────────────┤

### 6.2 交互

- 点击专家卡片打开详情弹窗。
- 点击开场白时：
  - 派遣该专家到原对话。
  - 将开场白填入原对话真实聊天框。
  - 不自动发送。
  - 不跳转到新的对话。
- 点击底部按钮直接派遣，不写入开场白。
- 弹窗关闭后焦点回到原卡片。
- `Esc`、关闭按钮和遮罩点击均可关闭。

如果从专家组件页面进入详情，而当前没有可回填的对话上下文：

- 不要在页面底部临时生成聊天框。
- 点击派遣或开场白直接跳到真实的新建任务界面并挂上该专家，不要求选择已有目标对话。
- 选择开场白时将文本填入新建任务的真实聊天框，但不自动发送。

## 7. 专家编辑器

### 7.1 页签

- `基础信息`
- `高级功能`

两个页签位于同一个编辑弹窗或侧边面板中，不做成两个独立页面。

### 7.2 基础信息

字段建议：

| 字段 | 控件 | 要求 |
|---|---|---|
| 专家名称 | 单行输入框 | 必填 |
| 姓名或称呼 | 单行输入框 | 必填 |
| Tag | 多选器 | 可以选择多个 |
| 能力介绍 | 多行文本框 | 一段简短介绍 |
| 擅长领域 | 多行文本框 | 每行一个 |
| 开场白 | 多行文本框 | 每行一个 |
| 工作方式 / 系统提示 | 多行文本框 | 长文本 |

必须做到：

- `擅长领域`和`开场白`使用两个不同文本框。
- 两个文本框都采用“一行一个”的编辑方式。
- 保存时去除空行并按行生成数组。
- Tag 是多选，不允许用单选 Category 代替。

### 7.3 高级功能

```text
┌────────────────────────────────────────────────────────────┐
│ 基础信息   高级功能 (已选总数)                             │
├────────────────────────────────────────────────────────────┤
│ 该专家的能力范围                                           │
│ 3 Skill · 2 MCP · 8 本地工具                              │
│                                                            │
│ ┌──────────────────────┐  ┌──────────────────────────────┐ │
│ │ Skill               │  │ MCP                          │ │
│ │ [搜索]              │  │ [搜索]                      │ │
│ │ ☑ frontend-design   │  │ ☑ github       已连接       │ │
│ │ ☑ code-review       │  │ ☑ context7      已连接       │ │
│ │ ☐ docs-sprint       │  │ ☐ filesystem    可用         │ │
│ └──────────────────────┘  └──────────────────────────────┘ │
│                                                            │
│ ACECode 本地工具                                           │
│ ☑ file_read                  ☑ file_write                    │
│ ☑ file_edit                  ☑ AskUserQuestion               │
│ ☐ bash                       ☑ todo_write                    │
└────────────────────────────────────────────────────────────┘
```

Skill：

- 支持搜索和多选。
- 显示 Skill 名称、简述以及“全局 / 项目”等来源。
- 显示已选数量与总数量。

MCP：

- 支持搜索和多选。
- 显示服务器 ID、简述和连接状态。
- 专家配置只引用 MCP 服务器 ID，不复制密钥。
- 已配置但全局关闭的 MCP 仍可由专家显式勾选并在该专家上下文中启用；未配置或缺少凭据的 MCP 不能凭空启用。

ACECode 本地工具：

- 以真实工具注册表为准，不维护第二份虚构名单。
- 每个本地工具使用 checkbox，至少包含 `file_write` 和 `AskUserQuestion`。
- 继承全局时，全局启用/已注册的工具默认勾选，禁用或不可用的工具默认不勾；切换为专家显式配置时从这些可见默认值开始。
- 其他示例包括 `file_read`、`file_edit`、`grep`、`glob`、`bash`、`todo_write`、`vision_analyze`、`web_search`、`lsp`。
- 关闭后，该专家看不到对应工具。
- 专家显式 Skill、MCP、本地工具配置优先于全局启用/禁用状态，但不能安装/注册不存在的能力。
- 专家级配置不能绕过权限、用户确认策略、Plan/Dangerous 模式或沙箱。

### 7.4 保存与错误

- 保存按钮明确为 `创建专家` 或 `保存专家`。
- 保存期间进入 Busy 状态，避免重复提交。
- 失败时保留用户输入并在弹窗内显示错误。
- 取消或关闭有未保存内容时，应提示确认。

## 8. 专家团编辑器

### 8.1 成员配置

```text
┌──────────────────────────────────────────────────────────┐
│ 团队成员                          已选 3 人 · 1 位主理人 │
│                                                          │
│ [头像] 敏敏   产品经理 · 擅长需求拆解        [主理人] 移除 │
│ [头像] 吴八哥 后端开发 · 擅长系统架构      设为主理人 移除 │
│ [头像] 言之   UX 设计师 · 擅长交互流程     设为主理人 移除 │
│                                                          │
│ + 添加专家                                               │
├──────────────────────────────────────────────────────────┤
│                                      取消  保存专家团    │
└──────────────────────────────────────────────────────────┘
```

要求：

- 支持添加和移除专家。
- 恰好指定一位主理人。
- 成员行显示头像、姓名、角色与一条擅长描述。
- 成员选择器沿用专家的搜索和 Tag 筛选模式。
- 专家团不能通过团队配置扩大成员原本没有的权限。

## 9. 交互契约

| 操作 | 所在界面 | 结果 |
|---|---|---|
| 点击聊天框“+” | 真实对话 | 打开一级菜单 |
| 悬停或点击“专家组件” | 一级菜单 | 打开二级菜单 |
| 点击最近专家 | 二级菜单 | 派遣到当前对话并关闭菜单 |
| 点击最近专家团 | 二级菜单 | 派遣专家团到当前对话并关闭菜单 |
| 点击“更多专家” | 二级菜单 | 打开专家选择界面，保留当前对话和草稿 |
| 点击专家卡片 | 专家组件页面 | 打开详情弹窗 |
| 点击卡片“派遣” | 专家组件页面 | 跳到新建任务并挂上专家，不触发卡片详情 |
| 点击开场白 | 详情弹窗 | 跳到新建任务，挂上专家并填入真实聊天框，不自动发送 |
| 中途切换专家 | 真实对话 | 更新后续轮次的专家状态 |
| 点击专家状态旁 `×` | 新建任务/真实对话 | 清除绑定显示；已有会话不重建运行时上下文或 KV cache |
| 点击页面空白 | 菜单 | 关闭一级和二级菜单 |
| 按 `Esc` | 菜单或弹窗 | 关闭当前最上层界面 |

## 10. 状态变体

### 10.1 最近记录为空

- 二级菜单只显示“更多专家”。
- 不显示空提示。

### 10.2 专家列表为空

- 专家组件页面显示简洁空状态。
- 提供“清除筛选”或“查看全部”操作。
- 空状态仍然不能出现聊天框。

### 10.3 加载

- Tag 和卡片区域显示骨架状态。
- 不用整页旋转加载图遮挡已有内容。

### 10.4 错误

- 加载失败显示局部错误和重试。
- 派遣失败保留原专家状态，并用 toast 或就近错误提示说明。

### 10.5 能力不可用

- 全局禁用但已安装/已配置的 MCP、Skill 或工具显示“专家可启用”，允许勾选。
- 未安装、未配置、缺少凭据或未注册的能力显示不可用，不能凭空启用。

## 11. 响应式约束

- 宽屏：专家卡片使用多列网格。
- 中等宽度：自动减少列数，不产生横向页面滚动。
- 窄屏：卡片单列，详情和编辑器接近全屏。
- Tag 行允许横向滚动。
- 聊天框二级菜单在空间不足时改变展开方向，但仍保持单行 item。
- 弹窗底部主操作始终可见，内容区内部滚动。

## 12. 视觉方向

- 与 ACECode 现有设置和管理页面保持一致。
- 使用紧凑、克制的桌面生产力工具风格。
- 亮色和暗色主题都要成立。
- 主色用于选中态、焦点和主要操作，不要大面积铺蓝。
- 卡片边界清晰，但避免厚重阴影和过度圆角。
- 字体、间距、边框、表单和状态色优先复用 ACECode 现有设计 Token。
- SVG 图标应使用一致的线性风格。
- 不使用 Emoji 作为正式功能图标。

## 13. 明确禁止项

- 不得在专家组件页面底部放聊天框。
- 不得在专家组件页面加入悬浮聊天输入条。
- 不得把 Tag 设计成互斥 Category。
- 不得在专家卡片上用开场白代替擅长领域。
- 不得把最近专家 item 做成双行。
- 无最近记录时不得显示“没有最近的专家”。
- 不得保留“浏览器”菜单项。
- 不得用“使用”“召唤”等其他文案替代“派遣”。
- 从真实对话选择专家后不得切屏或新建对话；从独立专家组件页派遣则必须进入新建任务。
- 开场白不得自动发送。
- 专家显式能力配置可以覆盖全局启用/禁用状态，但不得绕过 ACECode 的权限、确认策略或沙箱。

## 14. 下一位设计 Agent 的交付物

至少输出以下高保真状态：

1. 专家组件页面——专家页签默认状态。
2. 专家组件页面——专家团页签。
3. 多 Tag 筛选状态，证明同一专家可出现在不同 Tag 中。
4. 专家详情弹窗。
5. 专家编辑器——基础信息。
6. 专家编辑器——高级功能。
7. 专家团成员编辑器。
8. 真实对话页面上下文中的“+”一级菜单与专家二级菜单。
9. 二级菜单无最近记录，仅显示“更多专家”的状态。
10. 专家已派遣和中途切换后的真实对话状态。

第 8～10 项必须画在真实对话页面或独立聊天框组件稿中，不能附加在专家组件页面底部。
