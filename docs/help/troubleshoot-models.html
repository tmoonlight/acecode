模型连接与认证问题

按服务商、预设、实际端点和错误类别逐项检查，避免把所有失败都归因于模型本身。

本页内容
  • 先核对连接的四项信息
  • 按错误类别处理
  • 探测与账号授权

先核对连接的四项信息

进入模型页编辑目标预设，确认 Provider 类型、Model ID、Base URL 或完整端点及认证来源。预设名称只是 ACECode 中的标识，可以与 Model ID 不同。复制名称相同的预设时，尤其要检查实际地址是否一致。

保存后确认当前任务选中的是这份预设。更新默认模型主要影响后续选择；正在运行的请求不会因为刚刚编辑字段而瞬间改用新参数。

按错误类别处理

现象优先检查
401 / 认证失败密钥是否有效、是否已过期、请求是否发送到正确服务；托管账号是否仍授权。
403 / 无权限账号、项目或组织是否有目标模型权限，是否受服务策略限制。
404 / 模型不存在Model ID、Base URL 与端点路径；区分找不到路由和找不到模型。
400 / 参数不支持协议是否匹配，思考、采样、工具与输出参数是否被该模型接受。
429区分临时频率限制与余额、套餐或硬配额不足，阅读服务返回的具体说明。
Failed to fetch / 连接失败先确认失败请求指向本机 daemon 还是模型服务，再检查服务、代理和网络。

服务端错误文字有时比状态码更具体。反馈时保留错误类别和时间，删去密钥、认证头与私密请求内容。不要通过关闭证书验证来掩盖错误的地址或系统证书环境。

探测与账号授权

探测失败先检查服务是否支持模型目录接口；没有返回完整能力信息，不一定表示对话接口无法使用。查看已有探测结果可能来自缓存，需要重新请求服务时点击重新探测。

GitHub Copilot 使用模型页的连接 GitHub 流程完成设备授权，确认浏览器授权后回到 ACECode 检查连接状态。退出连接后需要重新授权，不能用普通自定义接口的密钥表单代替托管流程。

先用一条短文本验证基础请求，再测试图片、思考或工具调用。某项能力失败时按模型能力与参数核对，而不是同时修改所有配置。
