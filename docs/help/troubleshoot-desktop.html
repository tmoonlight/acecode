桌面、终端与远程连接问题

把桌面壳、后台服务、浏览器连接和项目工具分开检查，先保留现场再采取重启等操作。

本页内容
  • 桌面白屏、连接失败或意外退出
  • 终端不可用或命令环境不同
  • 远程 Web 无法连接
  • Agent 浏览器或预览功能不可用

桌面白屏、连接失败或意外退出

记录发生时间、应用版本、最后一次操作和完整错误。先查看最近 desktop 与 daemon 日志，确认是窗口、托管后台还是模型请求出了问题。只看到 Failed to fetch 不能直接判断模型服务故障。

桌面使用专门的托管运行目录 ~/.acecode/run/desktop-shared/，启动时检查进程身份、心跳和协议兼容性。普通 acecode daemon status 查看的是独立后台目录，结果不能直接替代桌面托管状态。

需要重新启动前，先保存尚未保存的文件草稿并记录正在运行的任务。macOS 关闭窗口通常只是隐藏应用；真正退出后是否继续运行后台由全局偏好决定，应区分这两种动作。

终端不可用或命令环境不同

在底部终端选择正确的 Shell，并检查命令实际运行目录。桌面启动方式可能与外部终端继承不同的 PATH、代理或虚拟环境，外部命令可用不代表后台环境中也可用。

原生 PTY 与兼容终端模式的能力不同。兼容模式不适合 vim、top 等需要完整交互终端的程序；需要这些工具时使用可用的原生终端或外部终端。

TUI 按键不符合预期时，检查输入焦点、下拉菜单和权限弹层。Ctrl+P 等按键会因当前模式而改变作用；退出使用 /exit，或按提示连续两次 Ctrl+C。

远程 Web 无法连接

  1. 先在服务所在机器打开实际本机 Web 地址。
  2. 检查远程 Web 模式已开启，并使用复制连接中的代理地址与端口。
  3. 确认目标设备能解析主机名并到达端口，检查防火墙或网络策略。
  4. 从当前运行服务重新复制连接，排除旧 Token。
  5. 观察是 HTTP 请求失败还是 WebSocket 断开，再查看后台与代理日志。

daemon 固定监听回环地址，远程接入通过独立代理提供。不要把出站模型代理配置当作远程 Web 配置。服务重启、代理切换或端口配置变化后，先刷新实际连接信息。

Agent 浏览器或预览功能不可用

确认使用的是支持原生桥接的平台桌面构建。对于浏览器页面，检查该页签是否共享、是否已加载、是否已关闭。外部浏览器标签页不会自动变成 ACECode 的可控页签。

文本文件在工作区外只读是预览边界；保存冲突说明磁盘内容可能已改变。先比较当前草稿和磁盘文件再处理，避免覆盖其他程序的新修改。参考桌面端和Agent 浏览器。
