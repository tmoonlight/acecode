日志与问题反馈

提供能复现的问题描述和对应时间范围的日志，帮助快速定位到具体会话与运行环节。

本页内容
  • 先整理问题描述
  • 通过问题反馈页面提交
  • 手动查找日志

先整理问题描述

问题描述模板
ACECode 版本：
操作系统与架构：
使用入口：桌面 / TUI / CLI / Web
发生时间与时区：
复现步骤：
预期结果：
实际结果与错误文字：
是否每次发生：
已经尝试的处理：

给出最短的复现步骤，以及第一次失败前最后一个成功动作。涉及模型时提供 Provider 类型、Model ID 和脱敏后的错误；涉及文件时提供必要的路径结构与差异，避免提交整个私有项目。

通过问题反馈页面提交

进入设置 > 问题反馈，填写反馈内容。页面默认附带最近的 desktop 与 daemon 日志；需要关联一次具体任务时，在会话选择中选中它。

没有选择会话时，不附带会话数据库或会话记录。选中后会显示将附带的会话，可以清除选择。点击提交反馈会上传反馈包，成功后显示包文件名；上传失败时查看错误及可能返回的本地包路径。

选择会话意味着把其内容加入反馈范围。提交前确认其中没有不应共享的业务资料、凭据或私人内容。页面没有提供的本地导出操作不要当成上传按钮的替代行为。

手动查找日志

运行方式常见日志位置
TUI当前工作目录中的 acecode.log。
独立或桌面后台数据目录/logs/daemon-日期.log。
桌面壳数据目录/logs/desktop-日期.log。
无界面 CLI数据目录/logs/headless-日期.log。

个人模式的数据目录为 ~/.acecode，Windows 服务使用 %PROGRAMDATA%/acecode。尽量截取事件前后连续一小段日志，保留时间、错误类别和相关 ID，遮挡认证头、Token、密钥及不必要的个人信息。

也可以在项目官方问题页提交经过整理的描述。不要直接上传主配置文件、run/token 或整个用户数据目录；需要补充材料时按实际诊断范围提供。
