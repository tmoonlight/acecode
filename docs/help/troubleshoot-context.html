上下文超限与请求失败

上下文超限、短暂网络故障和任务逻辑失败需要分别处理。先读取当前状态，再决定压缩、等待或修复配置。

上下文超限

检查所用模型真实支持的上下文窗口与最大输出限制。模型请求还包含项目规则、工具定义、历史消息、图片等内容，不能只按当前输入框字数估算总长度。

  1. 确认预设中的窗口与输出配置符合服务商限制。
  2. 减少大日志、重复附件和无关历史。
  3. 有可用模型连接时提交 /compact，再检查压缩是否完成。
  4. 仍无法继续时，新建任务并附上目标、已确认结论、未完成事项和必要路径。

单纯增大本地窗口数值不会扩展服务端限制。修改模型配置后，确认后续请求确实使用了更新后的预设。

网络暂时不可用，等待重试

临时网络故障、超时或可恢复的服务端错误会进入自动重试。界面会显示重试状态和等待信息；间隔逐步增加，最长可能达到 20 分钟，次数本身没有固定上限。

在同一进程持续运行期间可以等待恢复，也可以使用停止操作取消。重试针对失败的模型采样，不会为了这次重试重新执行已经成功的工具。停止或进程退出后，不应期待这段等待自动在新进程中继续。

认证错误、确定的无权限、硬额度不足、非法参数和上下文超限不适合靠无限等待解决。先检查具体错误，修复后再发送一条小请求验证。

有部分输出但没有完成

部分文字或部分工具成功不表示整项任务完成。检查最后状态是完成、失败还是中断，查看最后一个错误，并核对文件是否已经变化。继续时说明从哪一步接着做，避免重复已经完成的外部操作。

压缩失败时保留错误记录，不把进度提示当成成功标记。无界面 CLI 应同时检查退出码与 JSON 中的 is_error；API 客户端应检查终态 outcome，而不只依据收到 done 事件。

需要提交问题时，记录模型预设、最近成功步骤、失败时间和上下文状态，参见日志与问题反馈。
