工具、技能与 MCP 问题

先判断是能力没有加载、运行条件不满足，还是调用后的业务结果失败，再处理对应环节。

本页内容
  • 工具不可用或执行失败
  • 技能没有出现或没有应用
  • MCP 连接或工具加载失败
  • Hook 没有执行

工具不可用或执行失败

用 TUI 的 /tools 或 CLI 的 acecode -p --list-tools 检查当前工具清单。平台、功能开关、专家能力范围及运行依赖都可能影响可用性。Web 设置工具页不是完整的工具注册清单。

权限被拒时检查请求范围与当前模式；命令找不到时检查后台所在环境的 PATH；文件找不到时检查真实工作区与工作树路径。文件精确编辑失败，应重新读取目标内容，不能不断重试同一个已失效片段。

工具正常执行但测试失败时，阅读测试错误，继续修复代码。语言服务器无反馈时先按LSP 与代码诊断确认其安装和项目环境。

技能没有出现或没有应用

  1. 确认是一个完整目录，存在有效的 SKILL.md 和必需的名称、描述。
  2. 检查目录位于当前启用的全局、项目或额外扫描位置。
  3. 重新加载技能，并检查禁用状态、同名来源与解析诊断。
  4. 在一个小任务里明确选择技能，确认辅助文件的相对路径。

复制技能正文到聊天不等于安装技能；安装成功也不等于它需要的脚本依赖已准备好。CLI 默认不启用技能，需要显式选择。具体步骤见技能。

MCP 连接或工具加载失败

先确认 JSON 合法且已经保存，再查看服务器状态和工具清单。stdio 服务检查 command、args、环境变量和解释器；远程服务检查 sse / http 协议、URL 拼接、认证与代理。

修改服务器配置后使用 Reload 或 /mcp reconnect 服务器名 重连；重新加载编辑区文本与重建连接不是同一个操作。显示“重启 daemon 后生效”时按提示完成重启。

连接成功但没有工具可能是服务没有提供 tools，或初始化、能力协商失败。模型调用时失败则进一步查看工具参数和服务返回内容。先用一个明确的简单工具验证，不要一次同时新增多个服务器后猜测是哪一个导致问题。

Hook 没有执行

在钩子页刷新并查看来源、信任状态、事件和匹配规则。待审核项、被禁用项、未受信任项目或不支持的处理器会被跳过。脚本的解释器、工作目录和超时同样需要正确。

修改命令后可能需要重新信任。连接器的首次启动认证另有规则，不会因为重启或切换连接器开关就自动再次执行。参见 Hooks 与连接器。
