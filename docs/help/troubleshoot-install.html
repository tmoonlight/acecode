安装、启动与更新问题

先确认安装来源、实际启动文件和运行环境，再处理依赖、端口与更新问题。

本页内容
  • 找不到 acecode 命令
  • 启动失败或窗口立即退出
  • 更新失败或仍显示旧版

找不到 acecode 命令

  1. 重新打开终端，让新 PATH 生效。
  2. 检查安装目录中是否存在对应程序，区分终端版与桌面程序。
  3. 检查命令解析到了哪一个文件，排除旧版或其他安装路径。
  4. 直接运行目标程序确认版本，再修复 PATH。
Windows PowerShell
Get-Command acecode -All
acecode --version
macOS / Linux
command -v acecode
acecode --version

如果使用 npm 安装，检查 Node.js、npm 与全局可执行目录是否属于同一环境。公司电脑可能有多套 Node 版本或终端环境，旧终端不一定继承新的安装路径。重新安装前先按安装确认平台与安装方式。

启动失败或窗口立即退出

记录系统版本、CPU 架构、安装包名称和错误提示。Windows 桌面需要可用的 WebView2 环境；macOS 需要与芯片匹配的应用；Linux 二进制还受到系统运行库与执行权限影响。

独立后台启动失败时，先运行 status；确认没有正在使用的同一后台后，使用前台模式查看错误。桌面托管后台有自己的运行目录，不能仅凭普通 daemon status 判断桌面进程是否存在。

独立后台 · 前台命令会占用当前终端
acecode daemon status
acecode daemon --foreground

端口占用会导致独立 daemon 明确拒绝启动，不会自动扫描备用端口。先识别占用程序及使用者，再决定关闭该程序或为独立后台明确指定其他端口。

更新失败或仍显示旧版

检查更新源是否可访问、磁盘空间是否足够，以及目标程序是否被正在运行的进程锁定。保留错误输出，确认启动路径后按原安装方式重试更新，避免同时维护多个互相覆盖的副本。

更新命令成功后，重新打开目标应用并核对版本。桌面启动器与配套 daemon 应来自同一套安装包；不要只替换其中一个程序来测试正式安装。

配置错误触发自动回滚时，先查看回滚提示与备份位置，修复目标字段。卸载通常不等于清除所有个人数据；按更新与卸载选择是否保留模型和历史。
