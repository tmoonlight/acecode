消息渠道与远程控制

通过已经安装的渠道插件把一个 ACECode 会话连接到外部消息平台，或使用手动 Webhook 进行集成。

本页内容
  • 准备并连接消息渠道
  • 在渠道中切换会话
  • 查看状态、解绑与手动接入

准备并连接消息渠道

先按渠道插件的说明安装它的可执行程序、完成平台认证并取得 manifest 文件。ACECode 使用 remote_control.channels 保存插件配置，使用 remote_control.default_channel 指定默认渠道。只输入消息平台名称不会自动安装插件。

JSON · 合并到主配置，路径与 settings 按插件说明填写
{
  "remote_control": {
    "default_channel": "my-channel",
    "channels": {
      "my-channel": {
        "manifest_path": "/absolute/path/to/channel-plugin.json",
        "timeout_ms": 10000,
        "settings": {}
      }
    }
  }
}

在要绑定的会话中提交 /rc，它是 /remote-control 的别名，会激活默认渠道。确认返回已连接状态后，从消息平台发一条简单请求，检查是否进入目标会话并能收到回复。

在渠道中切换会话

daemon 托管的已连接渠道可使用以下会话导航命令。这些控制命令由后台处理，不会作为普通问题交给当前模型。

在渠道发送结果
/sessions列出最近十个普通、未归档会话。
/sessions more 或 /sessions all查看完整目录。
/sessions search 关键词搜索最多五个匹配结果。
/sessions 2选择最近一次列表中的第 2 个会话。

/session 和 /resume 是同一组渠道导航的别名。列表包含有工作区与无工作区的普通任务，不包含已归档任务和子代理。切换成功后以确认信息中的会话名称为准，再发送后续工作。

目标会话无法恢复时，原连接会保留。运行中的控制请求还在处理时，不要连续发送大量列表和切换命令。桌面前端可以收到切换提示，但渠道本身的会话选择不依赖桌面窗口保持打开。

查看状态、解绑与手动接入

在 ACECode 会话中查看状态与解除绑定
/rc show
/rc off

show 展示当前连接、入站与出站状态，内容可能包含认证信息，不要直接公开截图。off 解除当前绑定。daemon 托管模式会保存绑定会话并在后续启动时尝试恢复，单纯关闭桌面窗口不等于主动解绑。

手动集成使用 /remote-control on 启动本地入站服务，再通过 /remote-control url <webhook-url> 指定出站地址。入站使用 POST /rc/send、X-ACECode-RC-Token 请求头和 {"text":"消息"} 正文；按 show 的实际地址接入。

远程消息控制与远程 Web是两套入口，认证头与端口也不同。需要实现自己的渠道时，参见渠道插件协议。
