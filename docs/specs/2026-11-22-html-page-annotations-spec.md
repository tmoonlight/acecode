## Problem Statement

在桌面端让 agent 改 HTML 页面时，用户只能靠文字描述"那个标题再大一点"，模型猜错一轮就要重来。批注功能本该解决这件事，但现在的实现把批注绑在浏览器页签上、把发送按钮放在页面工具栏里，于是用户撞上三个具体的坑：

1. **关掉页签，写到一半的批注全没了。** 用户经常一边看页面一边在对话里问问题，顺手关掉用不上的页签，回来发现批注和描述一起消失。
2. **两个发送按钮是两套东西。** 页面工具栏的发送只发页面上的批注、还带着批次回执与重试对账，完全看不见输入框里用户刚敲的话；输入框的发送又不知道有批注在等。用户从哪头发、发出去的是什么，全凭记忆。
3. **发送失败会让 agent 把同一处改两遍。** 网络抖一下、确认事件丢一次，界面就回滚，用户以为没发出去又点一次；而消息其实已经入库，模型收到两条一样的批注，重复执行同一处修改。

另外两个小一点的坑：截图是发送时才截的，关掉页签就没有图；mac 上目标在视口外时截图必然拿不到，直到点发送那一刻才报错。

## Solution

把批注从"页签的附属物"变成"会话里的一份待发清单"：

- **记录归会话**。关页签不丢批注，它们变成"页面已关闭"，仍可改文字、删除、发送。
- **待发清单就是输入框上方的一张卡片**。按页签分组，每条显示缩略图、元素标签和描述，右侧是铅笔和垃圾桶。点铅笔回到页面继续改（页签没了就弹窗只改文字），点垃圾桶删掉并给 5 秒反悔。
- **组装一处，触发三处**。消息只在输入框组装一次；输入框发送、页内工具栏发送、浮窗 Ctrl+Enter 三者等价，都是「把输入框里的内容和所有待发批注批量提交」，用户敲的话与整批批注合并成一条消息，模型一次读全。
- **截图在保存批注时就截好**，发送只上传。关页签、刷新都不会让图消失。
- **失败不再靠猜**。40 秒没收到确认时，先按客户端消息标识核对消息是否真的入库：入库就当成功，没入库才回滚并提示重试。宁可让用户看到一条"可能已发出"的记录，也不制造重复。
- **发送完成的消息只读**。消息是对话记录，模型已经按当时的描述执行过；能改就等于改历史。

## User Stories

1. 作为一名在桌面端改页面的用户，我想圈出一个元素后直接调样式并写一句"这里太大了"，这样我不必用文字描述元素在哪。
2. 作为一名用户，我想在页面上看到带编号的图钉，这样我知道自己标了几处、分别在哪。
3. 作为一名用户，我想按住工具栏上的按钮看到页面原本的样子，这样我能确认改动是不是过头了；这个动作不占用任何键盘快捷键。
4. 作为一名用户，我想松手就回到改后的样子，这样对比不打断我的编辑节奏。
5. 作为一名用户，我想这个对比只在我按住鼠标时生效，这样我在别处敲键盘不会莫名其妙让页面闪一下。
6. 作为一名用户，我想在对比时看不到图钉和描边，这样原图是干净的原图。
7. 作为一名用户，我想点一下就把所有批注标记藏起来，这样我能看清页面本身而不取消我的修改。
8. 作为一名用户，我想"隐藏标记"保持我按下的状态，这样我不用一直按着。
9. 作为一名用户，我希望按住看原图时看到的是页面最初的样子，而不是我上一次改之前的样子，这样多次调整同一个属性时基准不会漂。
10. 作为一名用户，我想在浮窗里按 Enter 就把这条批注加进待发清单，这样我能连着标好几处。
11. 作为一名用户，我想按 Shift+Enter 在描述里换行，这样我能写多行说明。
12. 作为一名用户，我想按 Ctrl+Enter 就"保存这条并整批发出去"，这样急的时候一步到位。
13. 作为一名用户，我想在输入框上方看到一张待发卡片，这样我知道还有几条没发。
14. 作为一名用户，我想在卡片上看到每条的缩略图，这样我不用回忆自己标的是哪一块。
15. 作为一名用户，我想看到每条的元素标签（div / button / input），这样我能快速区分几条相似的批注。
16. 作为一名用户，我想让卡片按页面分组，这样我在多个页签之间来回看时不会混。
17. 作为一名用户，我想在批注很多时让卡片内部滚动而不是把对话挤走，这样我还能看见正在说的话。
18. 作为一名用户，我想点卡片上的铅笔就回到那条批注继续改，这样不用重新圈一遍元素。
19. 作为一名用户，我想回到页面时描述框是填好的、光标在末尾，这样我能直接接着打字。
20. 作为一名用户，我想在页签已经关掉时仍能改这条的文字，这样我不会因为手滑关页签就丢掉想法。
21. 作为一名用户，我不想在页签关掉后看到"调整样式"的按钮，因为那时它点了也没用。
22. 作为一名用户，我想删掉某条批注后 5 秒内还能反悔，这样误点不至于毁掉一段描述。
23. 作为一名用户，我想在关闭页签后仍能看到并发送那些批注，这样我不必为了发送而重新打开页面。
24. 作为一名用户，我想在输入框里既写自己的话又带上批注，这样模型能同时理解我的指令和精准改动。
25. 作为一名用户，我想点一次发送只产生一条消息，这样模型不会把同一批批注读两遍。

26. 作为一名用户，我想在页面上批注完直接点工具栏的发送，而不用先切回对话，这样我不丢掉刚在页面上形成的判断。

27. 作为一名用户，我想无论从工具栏还是从输入框发送，结果都完全一样，这样我不用记哪个按钮发什么。
28. 作为一名用户，我想在发送后立刻看到图钉和卡片清空，这样我知道"发出去了"。
29. 作为一名用户，我想在网络不稳时不被误判为失败，这样我不会重复发送、让模型改两遍。
30. 作为一名用户，我想在真的没发出去时把批注找回来重发，这样我不用重标一遍。
31. 作为一名用户，我想刷新页面后批注和预览还在，这样改完样式刷新看一眼不会丢。
32. 作为一名用户，我想在页面结构变了以后，那些对不上的批注被标成"已失效"而不是偷偷改错元素。
33. 作为一名用户，我想看到每条批注对应的大致源码位置（文件行号或组件名），这样我知道该让 agent 改哪个文件。
34. 作为一名用户，我想在消息里看到每条批注的局部截图，这样我回看对话时知道当时指的是哪一块。
35. 作为一名用户，我想让发出去的批注卡片只能看不能改，这样对话历史和实际执行不会对不上。
36. 作为一名用户，我想在一个会话的多个页签之间自由切换，批注互不干扰。
37. 作为一名用户，我想在重启应用后从干净状态开始，这样不会莫名其妙冒出一堆旧批注。
38. 作为一名用户，我想在页面里没有批注时看不到那张卡片，这样界面保持干净。

## Implementation Decisions

- **记录权威上提到会话级**。批注记录、发送中集合、按页签分组的编号，全部由一个新引入的会话级批注存储持有；每个页签的批注会话只保留选区、预览、文档标识与命令下发，不再持有记录。
- **记录四态**：`live`（目标有效）、`replayable`（文档已替换、等待重放）、`stale`（重放失败或值已被改动）、`orphan`（页签已关闭）。四态决定能否画图钉、能否重放、能否调样式，但**都允许发送**（失效的标 `target_invalid`）。
- **关页签 = 转 `orphan`，不销毁**。页签关闭时把该页记录迁到会话存储的孤立集合，并广播一次"该页已空"。
- **命令面分两档**：查询/预览类命令（读取快照、预览样式、预览文本、按住原图、隐藏标记、模态挂起、下发图钉）不占串行闸门，可并发、可覆盖；编辑类命令（开始/退出/取消/保存/加目标/加区域/选择/丢弃/重放/打开已有记录/更新描述/删除记录）串行并带序号防迟到。此前所有命令共用一个闸门，按住原图的手感直接受害。
- **图钉由原生全量下发**，页内运行时不再自己决定画哪些图钉、编号是几。每次记录集合变化都下发完整列表，页内整体替换（幂等），删一条后编号自动前移。
- **原始值（baseline）必须是首次触碰值**。多次修改同一属性时，按住看原图看到的必须是页面最初的样子；中间态不得写进记录。样式层要能做到"忽略本层已声明的样式"取值，文本层不得把已保存的值叠加进基准。
- **重放带观察窗口**：页面加载完成后立即重放一次，随后用 DOM 变更观察（节流 300ms）驱动重试，窗口 3 秒、最多 10 次；窗口内"元素还没渲染出来"不算失效。重放每个属性前先比对实时值是否仍等于原始值，不相等就标记失效、不写入。
- **截图在保存批注时生成**：一次视口捕获，按目标外接矩形裁剪，缩到宽 ≤512px 存进记录。待发卡片的缩略图与消息附件是同一张图；发送阶段不再捕获。视口外或捕获失败时该条标记无图，卡片退化为标签 + 文本片段。
- **组装唯一、触发三路**：消息只在会话输入框（composer）组装一次（`submitWithAnnotations()`）。输入框发送按钮、页内工具栏发送按钮、浮窗 Ctrl+Enter 都调它，参数与结果完全一致；工具栏按钮不自己组装 payload、不自己 POST。提交范围是会话全量（跨页签 + 已关闭页签），按钮上显示总条数；输入框草稿会一并发出。
- **消息合并**：`{用户文本}\n\nPage annotations\n{JSON}`。无用户文本时保持现状（只发载荷）。解析从"文本以固定头开始"放宽为"末尾存在分隔段"，卡片渲染时遮蔽 JSON 段、保留用户文本。
- **发送状态只有一个中间态**：点发送即把记录移出待发集合并清空图钉与卡片；收到该消息的确认事件后彻底丢弃；失败或超时则放回集合并重排编号。
- **超时自查**：40 秒未确认时，按客户端消息标识查询消息是否已入库。查到 → 视为成功；查不到 → 回滚；查询自身失败 → 不回滚，只提示"可能仍在发送"。
- **待发卡片的数据来源**：原生在任一页签的记录变化时都广播该页签的记录快照，前端按"会话 → 页签"归并，并单独维护孤立记录集合。卡片订阅这份归并结果，不读消息载荷。
- **可调整样式只有一条判定**：记录为 `live` 且页签存活且文档标识匹配。两个编辑入口共用这条判定，不得各写一份；`replayable` 也一律隐藏「调整」，因为重放未完成时基准是脏的。
- **编辑入口两条路径**：页签存活时激活页签 → 让页面回到批注模式 → 打开该条批注框（回填描述、光标置末尾、高亮图钉、差异还原为草稿）；页签已关时弹窗只改文字，目标定位信息只读。
- **删除即时生效 + 5 秒撤销**，不做二次确认弹窗。
- **已发送的消息卡片只读**：不提供编辑、删除、复制或"回到页面修改"。消息级的通用复制按钮保留，且复制出去的是人读文本而不是原始 JSON。
- **导航不作废记录**：刷新/前进后退只把记录转成待重放，不清空。

## Testing Decisions

好的测试只断言外部可观察的行为，不断言内部字段或实现细节。这个特性有四个天然边界：

1. **原生批注存储与命令面**（既有单测缝）。断言"发出这些命令后，快照里能读到什么"：新建/删除/丢弃后的编号连续性、关页签后记录仍可读、四态转换、查询类命令互不阻塞、发送中记录不计入待发数且不下发图钉。既有同类测试就是这个缝的范本，仍在同一个测试可执行体内跑。
2. **端到端发送**（既有浏览器集成缝，最高点）。一条链路覆盖：保存（生成缩略图）→ 关页签 → 卡片仍可见 → 弹窗改文字 → 输入框带文字点发送 → 只产生一条消息 → 载荷可被解析出用户文本与各条批注 → 收到确认后清空。以及超时三分支：已入库按成功收尾、未入库回滚、查询失败不回滚。再补一条等价性用例：同一状态下分别从输入框与工具栏发送，产生的请求体与消息条数完全一致。
3. **组件行为**（既有组件测试缝）。浮窗的按键语义（Enter 添加 / Shift+Enter 换行 / Ctrl+Enter 保存并发送）、按住原图与隐藏标记互不干扰、按住原图不响应空格与 Enter、`adjustable` 判定在四种状态下的取值、卡片 5 行封顶与滚动。
4. **归并器**（新增的唯一一个缝）。待发卡片的数据来源是一个纯函数：输入"若干页签各自的记录快照 + 孤立集合"，输出"按会话分组的展示列表"。它没有 DOM、没有异步，适合用表驱动测试覆盖空、单页、多页、孤立、同一页签反复更新这几种输入。

不新增其他缝。服务端只加一个按客户端消息标识查询的读接口，沿用现有 Web 冒烟测试的写法断言"建了消息能查到、没建查不到"。

## Out of Scope

- 手绘标注（自由笔迹）本轮不做，只做元素与矩形区域。
- 批注跨重启持久化：仍然只在当前运行期内存里，重启清空。
- 编辑已发送的消息：不新增消息编辑能力。
- 接收端按批次去重（收据机制）：明确不做，超时只做前端自查。
- 导航确认弹窗：不拦截用户操作。
- mac 视口外目标的截图：接受降级为无图，只做 UI 明示。
- 多人协作 / 批注共享给其他人。
