## 1. 一句话

让用户不用描述「那个标题再大一点」，而是**直接在网页上圈出来**，写完想怎么改，一次发给 AI。

## 2. 为什么做

现在用户想让 AI 改一个网页的样式或文案，只能用文字说。模型猜错一轮，用户要重新解释一遍，来回三四次才对齐。批注功能把「指哪里」和「改什么」变成可点选、可预览、可发送的一件事。

当前版本有三个具体的坑，用户已经在踩：

**坑一：关掉页签，写到一半的批注全没了。**
用户常常一边看页面一边在对话里问问题，顺手关掉用不上的页签。回来发现批注和描述一起消失，只能从头再标一遍。

**坑二：两个发送按钮是两套东西。**
页面工具栏上的发送只发页面上的批注，看不见用户在输入框里刚敲的话；输入框的发送又不知道有批注在等。用户从哪头发、发出去的是什么，全凭记忆。

**坑三：发送失败会让 AI 把同一处改两遍。**
网络抖一下、确认消息丢一次，界面就回滚，用户以为没发出去又点一次。而消息其实已经入库，模型收到两条一样的批注，把同一处改了两遍。

## 3. 目标用户与场景

| 维度 | 说明 |
|---|---|
| 谁 | 在桌面端让 AI 修改网页（HTML / CSS）的用户 |
| 什么时候 | 看到页面某处不满意，想说清楚「就是这里」 |
| 前置条件 | 桌面端已打开一个网页预览，且处于某个对话会话中 |
| 成功的样子 | 用户标 2–3 处、写两三句话、按一次发送，AI 一次改对 |

## 4. 三个核心概念

| 概念 | 含义 |
|---|---|
| **批注** | 页面上的一条标记：一个编号图钉 + 描述 + 可选的样式调整 |
| **待发** | 还没发出去的批注。集中在输入框上方的一张卡片里，跨页签可见 |
| **已发** | 变成聊天记录里的一张卡片，只读，不能再改 |

## 5. 一次完整的使用（界面分镜）

1. 用户在网页上点「批注」进入批注模式，页面出现工具栏。
2. 鼠标滑过元素，元素出现轮廓，旁边浮出小卡片：标签名、尺寸、颜色、字体。**不点也能先看清是什么。**
3. 单击元素，弹出批注浮窗，可以写描述。
4. 需要改样式时点「调整」，改字号、颜色、间距……**页面上立刻看到效果**，不是改完才知道。
5. 点保存，元素上出现编号图钉，输入框上方出现这条待发批注。
6. 继续标第二处、第三处，甚至切到另一个页签标。**关掉页签也不丢。**
7. 在输入框里写「这几处一起改」，按发送。三处批注 + 这句话作为**一条消息**发出。
8. 聊天里出现批注卡片：页面标题、每条描述、每条的截图。AI 按图改。

## 6. 功能需求

### 6.1 批注模式与工具栏

- 进入批注模式后，页面上浮一个工具栏，随页面滚动保持可见，可拖动位置。
- 工具栏提供五个动作：**发送、隐藏标记、按住看原图、丢弃全部、退出批注模式**。
- 「隐藏标记」是开关：打开后所有图钉和预览效果隐藏，再点恢复。
- 「按住看原图」：**按住按钮**时页面回到修改前的样子，松开恢复。只有按住这一种方式，没有快捷键。
- 「丢弃全部」需要二次确认，确认后清空**当前页面**的批注（其他页签的不受影响），该页编号从 1 重新开始。
- 「退出批注模式」只收起编辑控件，已保存的图钉和预览效果保留。
- 浮窗打开时工具栏隐藏，避免挡视线。

### 6.2 选中与浮窗

- 单击元素即打开浮窗，不需要先点「批注」再点元素。
- 鼠标移出页面、窗口失焦、切到后台时，悬停轮廓与信息卡立即消失，不会留在页面上。
- 打开任何菜单或弹窗时，页面的轮廓与信息卡暂停显示，关闭后恢复，且只恢复一次。
- 浮窗可以拖动；表头与底部按钮固定，中间属性区可滚动。
- 描述最多 4096 字。

### 6.3 样式调整与实时预览

支持调整：文字内容、字体、字号、字重、字距、词距、文字颜色、背景色、透明度、圆角、边框颜色与粗细、宽高、内外边距、行间距与列间距。

- 所有调整**实时预览**，所见即所得。
- 只记录真正发生变化的属性，没改的不写。
- 取消只回滚这一次的改动，之前保存过的批注和预览不受影响。
- 宽高锁定默认关闭；打开后按当前宽高比联动。
- 内外边距支持四边分别设置，也支持上下、左右成对联动。
- 每个改过的属性都可以单独恢复原值。

### 6.4 待发批注卡片

- 位置：输入框正上方。
- 按页签分组，组头是页面标题；编号在组内连续。
- 每条显示：截图缩略图、元素标签、描述。
- 超过 5 条时卡片内部滚动，不把输入框顶走。
- 每条右侧有铅笔（编辑）和垃圾桶（删除）。
- 删除立即生效，**5 秒内可撤销**，撤销后恢复原编号。

### 6.5 编辑一条待发批注

- **页签还开着**：点铅笔 → 自动切到该页签、回到批注模式、打开这条的浮窗，描述回填、光标在末尾；「调整」可用，可以继续改样式。
- **页签已关闭**：点铅笔 → 弹出只有描述框、删除、取消/保存的对话框；没有「调整」（页面没了，无法比对样式）；目标定位信息只读。
- **编辑途中页签被关**：已输入的内容保留为草稿，这条转为「页面已关闭」，下次点铅笔继续编辑。

### 6.6 发送

**只有一个发送动作，三个入口**：

| 入口 | 触发 |
|---|---|
| 输入框的发送按钮 | 点击 |
| 页内工具栏的发送按钮 | 点击（按钮上显示会话级待发总条数） |
| 浮窗描述框 | `Ctrl+Enter`（先保存当前这条，再发送） |

三者**完全等价**，都是「输入框里的文字 + 本会话全部待发批注」，发成**一条**消息。不会出现「工具栏只发批注、输入框只发文字」的情况。

- 提交范围是**整个会话**：包括其他页签的批注、已关闭页签的批注。
- 输入框里没写的文字就空着，只发批注；两者都为空时发送按钮禁用。
- 发送过程中用户切换页签、继续加批注，不影响已发出去的那批；新加的留到下一次。

**超时与重复**：发出后 40 秒没收到确认，系统先自己去查「这条消息到底进没进去」，再决定怎么办。

| 情况 | 处理 |
|---|---|
| 查到了 | 视为成功，清空待发，不产生重复消息 |
| 查不到 | 批注退回待发、重排编号、恢复图钉，提示可重试 |
| 查询本身失败 | 不回滚，提示「可能仍在发送」，由用户决定重试还是撤销 |

### 6.7 已发消息

消息在聊天里是一张卡片，每张截屏配一行说明：

```
┌────────────────────────────────────┐
│                                    │
│       页面截屏（单击看大图）          │
│                                    │
└────────────────────────────────────┘
   商品详情页                [ 3 条注释 ]
```

**卡片结构**：

1. **页面截屏** —— 被批注页面（右侧预览区）的画面。单击打开大图。
2. **截屏下方一行** —— 左边是页面标题（小字），右边是 `X 条注释` 标签。X 是这一页的批注数量。

卡片本身没有其他按钮，也没有逐条展开的列表，保持安静。

**悬停标签看明细**：鼠标停在 `X 条注释` 上，浮出这一页的注释列表。

- 每条一行：左边是 HTML 元素类型（`div`、`input`、`p` 等），右边是这条批注的意见。
- 默认最多显示 5 条；超过 5 条时列表内部滚动，不把浮层撑高、不顶走聊天。
- 一条批注标了多个目标时，元素类型取主目标。

其他规则：

- 只有一条注释时标签写 `1 条注释`，悬停仍然显示那一行。
- **一条消息涉及多个页面时**，卡片按页面依次堆叠「截屏 + 标题 + 标签」，每张图只显示自己那一页的注释，hover 也只展开该页的条目。
- 截屏获取失败时，保留标题与标签，不放占位图或碎图。
- 卡片内**没有任何操作按钮**：不能编辑、不能删除、不能回到页面修改。
- 复制整条消息时得到纯文本摘要（页面标题 + 每条的元素类型与意见），不是原始数据。

### 6.8 异常与状态

每条批注有四种状态，决定它能做什么：

| 状态 | 用户看到 | 能做什么 |
|---|---|---|
| 生效中 | 图钉正常显示，预览可见 | 改描述、改样式、发送 |
| 待恢复 | 页面刷新后暂时没画上图钉 | 系统自动重放；成功后回「生效中」 |
| 已失效 | 图钉标为失效 | 只能改描述、删除、发送（消息里标注目标已失效） |
| 页面已关闭 | 卡片上标「页面已关闭」 | 只能改描述、删除、发送（消息里标注目标已失效） |

其他规则：

- 页面要刷新或跳转时，如果还有没保存或没发送的批注，先提示，默认「留在当前页」，**从不自动发送**。
- 页面刷新后，能重新定位到元素的批注自动恢复图钉；如果该元素当前的值已经被别人改过，标为「已失效」，不覆盖。
- 元素被删除时，标为「已失效」，**不会去找一个长得像的元素替代**。
- 没有可用会话时，发送按钮禁用并提示「请先选择对话」，而不是点了才报错。
- 所有错误都显示中文产品文案，不出现英文报错或机器码。

## 7. 用户故事

1. 作为一个要改网页的用户，我想直接在页面上点出要改的元素，这样我不用描述「左边那个灰色的小字」。
2. 作为一个要改网页的用户，我想在单击前就能看到元素是什么标签、多大、什么颜色，这样我点之前就知道有没有点错。
3. 作为一个要改网页的用户，我想一次标好几处再一起发，这样 AI 能一次改完，不用来回三轮。
4. 作为一个要改网页的用户，我想在标的同时写一句话说明整体意图，这样 AI 知道这几处是同一个诉求。
5. 作为一个要改网页的用户，我想改完样式立刻看到效果，这样我不用发出去才发现不合适。
6. 作为一个要改网页的用户，我想取消这次调整时不影响之前保存的批注，这样我敢反复试。
7. 作为一个要改网页的用户，我想把改过的属性单独恢复原值，这样我不用重新调一遍。

18. 作为一个要改网页的用户，我想删除后 5 秒内能撤销，这样误点不至于重标。
19. 作为一个要改网页的用户，我想在输入框和工具栏上都能发送，且结果一样，这样我不用记哪个按钮发什么。
20. 作为一个要改网页的用户，我想在写描述时按 `Ctrl+Enter` 直接发出去，这样我不用来回切鼠标。
21. 作为一个要改网页的用户，我想发送按钮上显示还有几条没发，这样我不会漏发。
22. 作为一个要改网页的用户，我想一次发出会话里所有批注（包括别的页签的），这样我不用逐个页签去发。

33. 作为一个要改网页的用户，我想复制这条消息时得到干净的文本，这样我贴到别处不会带一堆符号。
33. 作为一个要改网页的用户，我想已发送的批注不能被改，这样历史记录可信。
34. 作为一个要改网页的用户，我想页面刷新后批注还能回到原位，这样我不怕误刷新。
35. 作为一个要改网页的用户，我想元素被删掉时批注标为失效而不是乱指，这样 AI 不会改错地方。
36. 作为一个要改网页的用户，我想没选会话时发送按钮是灰的并告诉我原因，这样我不会白点。
37. 作为一个要改网页的用户，我想所有报错都是中文说人话，这样我知道下一步做什么。
38. 作为一个要改网页的用户，我想丢弃全部前被问一次，这样不会一键清空我标了半天的东西。
39. 作为一个要改网页的用户，我想页面上任何菜单或弹窗打开时轮廓不挡着，这样我能正常操作。
40. 作为一个要改网页的用户，我想切到别的应用再回来时页面上没有残留的浮层，这样界面不会看起来坏掉。

## 8. 关键规则速查

| 主题 | 规则 |
|---|---|
| 编号 | 按页面分组，组内从 1 连续；删除后撤销可恢复原编号；丢弃全部后该页从 1 重来 |
| 截图 | 保存批注时按元素区域裁剪，宽度不超过 512px；发送阶段不再截图 |
| 消息卡片配图 | 每个页面一张截屏（不是逐条小图），下方一行「页面标题 + X 条注释」 |
| 注释明细 | 悬停 `X 条注释` 展开，每条「元素类型 + 意见」，最多 5 条，超出滚动 |
| 无图情况 | 目标不在可视区域时该条保存为「无图」，待发卡片用元素标签 + 文本片段代替 |
| 发送范围 | 整个会话的全部待发批注（跨页签 + 已关闭页签） |
| 发送内容 | 输入框文字 + 全部批注，合成一条消息 |
| 超时 | 40 秒未确认先自查，再决定成功 / 退回 / 提示 |
| 保留期限 | 只在本次应用运行期间保留，重启后不恢复 |
| 语言 | 全部中文产品文案，不暴露技术错误 |

## 9. 验收标准

以下每条都能在一次演示里当场验证：

1. 单击元素直接开浮窗，没有多余的「批注」按钮。
2. 鼠标移出页面，悬停卡片立刻消失。
3. 改字号，页面实时变化；取消后回到改前，之前保存的批注不受影响。
4. 按住「看原图」，页面回到改前；松开恢复。按空格或回车不触发。
5. 标 3 处，输入框上方出现 3 条，编号 1/2/3，各带缩略图。
6. 关掉页签，批注仍在卡片里，标为「页面已关闭」。
7. 点铅笔，页签还开着就回到页面浮窗；页签关了就只有描述框。
8. 删除一条，5 秒内撤销，编号恢复。
9. 输入框写「一起改」+ 3 条批注，点发送 → 只出现一条消息。
10. 同一个场景改点工具栏发送，结果完全相同，按钮显示「3」。
11. 发送后立刻切换页签再加一条，已发的 3 条不受影响，新的那条第 4 号留下次。
12. 聊天卡片是一张页面截屏，下方一行显示页面标题与 `3 条注释`，卡片内无按钮；单击截屏可看大图。
13. 悬停 `3 条注释` 浮出三行明细，每行是元素类型 + 意见；标 7 条时浮层显示 5 行并可滚动。

## 10. 不做什么

- 不做移动端、不做纯浏览器版（仅在桌面端 Agent 浏览器内）。
- 不做多人协作批注、不做批注的评论回复。
- 不做跨会话的批注（批注属于某一个会话）。
- 不做批注持久化到磁盘（重启即清空）。
- 不允许对已发送的批注做二次编辑。
- 不自动发送、不自动跳转页面。
- 不提供批注的键盘快捷键。输入框内的回车换行、`Ctrl+Enter` 发送属于输入习惯，不算快捷键。

## 11. 已知取舍

**纯键盘用户无法使用「按住看原图」。**
这个能力设计成瞬时按住指针动作，没有对应快捷键。对完全不使用鼠标的用户，这一项不可用；其他功能不受影响。此取舍已确认接受。

**待发批注不做持久化。**
应用重启后未发送的批注会丢失。理由是避免「上次没发的批注」在下次启动时突然出现造成困惑。如果后续有用户反馈，可作为 v2 议题。

**「丢弃全部」按当前页面生效。**
本稿采用的口径是：用户在哪个页面上点丢弃，就只清空该页的批注，其他页签的待发批注保留。理由是这个按钮长在页面工具栏上，用户的心理预期是「清掉这个页面上的标记」。如果希望它是「清空整个会话」，需要另行确认——那会让工具栏承担跨页面的破坏性操作，风险更高。

**消息卡片的页面截屏，在保存批注时生成，发送时直接取用。**
不能等到发送才截屏：发送那一刻页面可能已被关掉、跳到别的地址，或在 mac 上目标不在视口内，用户只会看到一个「发送成功但没图」或「发送失败」的结果。所以口径是：每保存一条批注，顺带更新该页面的一张整屏图，同一页面只保留最新一张；发送时零捕获。
两点后果需要接受：一是删除最后几条批注后配图不会自动重截，仍显示删除前的画面；二是同一页面在两次发送之间多次保存，配图始终是最后一次保存时的样子。

## 12. 命名对照

| 产品说法 | 工程术语 |
|---|---|
| 生效中 / 待恢复 / 已失效 / 页面已关闭 | `live` / `replayable` / `stale` / `orphan` |
| 待发批注卡片 | 待发卡片（composer 上方） |
| 统一的发送动作 | 一处组装、三处触发 |
