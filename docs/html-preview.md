# HTML 文件预览与可视化编辑

文件详情打开 `.html` / `.htm` 时,默认显示渲染后的页面,不再显示源代码。⋯ 菜单与右键菜单里的「查看源代码 / 浏览页面」在两个视图之间切换。桌面版里,工作区内可编辑的文件在 ⋯ 左边多一个编辑按钮:进入编辑后点选页面元素,会出现选框和浮动工具栏。

做法参考了 WorkBuddy 与 Claude Design(2026-11-18 逆向两家安装包,只读源码、没有运行验证):

- 两家都用 srcdoc 隔离框显示页面,选框画在框里,工具栏画在外层。
- WorkBuddy 保存时用自己的节点模型重新生成整份文件:元素 id 会永久写进文件,doctype、引号写法和注释也会被改动。ACECode 不这样做。
- Claude Design 只编辑它自己的 `.dc.html` 格式,不处理普通 HTML。

## 显示

- 组件:[HtmlPagePreview.jsx](../web/src/components/HtmlPagePreview.jsx)。它带着 parse5,只在打开 HTML 时按需加载。
- 隔离框的 sandbox 只有 `allow-scripts allow-modals`,框是不透明源。**绝不加 `allow-same-origin`**:本机回环免 token,同源的页面脚本就能调用全部 daemon 接口。`htmlPageFrame.test.js` 守着这一点。
- 不透明源发出的请求带 `Origin: null`,daemon 会要求显式 token(`auth_result_for_request`),所以页面脚本调不到 `/api/*`。
- 页面里的相对路径资源:先由 `POST /api/files/html-site` 登记站点,在 doctype 之后插入 `<base href>`,指向 `GET /api/html-site/<id>/…`。细节见 [daemon-api.md](daemon-api.md)。
  - 站点号即凭证。
  - 只服务网页资源扩展名,`.env`、私钥这类文件一律 404。
  - 页面脚本用 `fetch` / XHR 读不到文件内容(拿不到跨源许可);模块脚本、字体、样式、图片照常加载(按 `Sec-Fetch-Dest` 给 `*`)。
  - 纯逻辑在 [html_site_handler.cpp](../src/apps/web/handlers/html_site_handler.cpp),测试是 [html_site_handler_test.cpp](../tests/web/html_site_handler_test.cpp)。
- 框内运行时 [htmlPageRuntime.js](../web/src/lib/htmlPageRuntime.js) 在用户脚本之前执行,职责如下:
  - 链接与 `window.open` 交给外层打开:外链用系统浏览器打开,站内链接在文件详情里打开那个文件,`#锚点` 在框内滚动;
  - 右键、Ctrl+S 等快捷键转发给外层;
  - 给 localStorage / sessionStorage / cookie 内存替身(不透明源下一访问就抛错);
  - 报告滚动位置,重新渲染后恢复。
- 运行时整段经 `toString` 拼进框里,**不能写中文字符串字面量**,也不能 import 其它模块。
- **框内发来的消息一律不可信**。每次渲染有一个随机 nonce,但它写在 srcdoc 的脚本里,页面脚本读得到,只用来丢掉旧渲染的消息,不是鉴权。所以:
  - 快捷键、右键菜单、打开链接 / 文件都要求外层此刻有用户激活(真实按键与点击会沿父级传上来,脚本伪造不了;Esc 只用于取消选中,例外);
  - 改文字只接受外层自己发起的那一次;
  - 其它修改只能由外层工具栏触发,且只在编辑模式里生效。

## 编辑:只改动过的那一小段

核心原则是写回源码时其余字节原样保留:不改动就保存,diff 为零;改一个样式,diff 只落在那个标签上。纯函数在 [htmlSourceMap.js](../web/src/lib/htmlSourceMap.js)。

- parse5(带源码位置)解析草稿,给 body 里每个有源码位置的元素编号。
  - head、`script`/`style`/`template`、SVG 内部图形不编号。
  - 编号作为 `data-ace-sid` 只插进送给框的副本,**不进文件**。
- 每个修改都是一次区间替换,同时让框内直接改 DOM,页面不重新加载:
  - 改样式:只重写那个标签的 `style` 属性,保留其余声明的原文。没有 `style` 属性就插在标签名后面。
  - 改文字:双击或点「编辑文字」,元素进入 `contenteditable="plaintext-only"`;按 Esc、Ctrl+Enter 或点到别处时提交,只替换开始标签与结束标签之间的内容。
    - 双击段落里加粗 / 带链接的几个字,进入的是整段文字所在的元素(沿行内元素往上找到有编号的文字叶子),不是里面那个 `<b>` / `<a>`;单击仍可单独选中它改样式。
    - 改字时选中框样式不变,浏览器给可编辑元素画的焦点框用 `adoptedStyleSheets` 去掉;工具栏照常显示,「编辑文字」按下,再点一次结束改字。
    - 在框里拖选出一段文字后,粗细、斜体、下划线、删除线、颜色、字号、链接只作用在这段文字上:框内临时切成 `contenteditable="true"` 跑浏览器的格式命令(`execCommand`),执行完马上切回纯文本,所以打字、粘贴、回车仍不会冒出 `<div>`。产物是 `<b>` / `<i>` / `<u>` / `<strike>` / `<a>` 与带 `style` 的 `<span>`,都在文字叶子允许的行内标签里。纯文本模式下浏览器不认 Ctrl+B / I / U,选中文字时由框内补上。
    - 字号命令只认 1–7 档:先套第 7 档,再把选区里这一档换成像素值。
    - 对齐是段落属性,有选区时也改整个元素;没有选区(只有光标)时,工具栏和改字前一样改整个元素。
    - **只有一条撤销栈**:改字时框里边打边交回外层(停顿 250 毫秒交一次,离开改字、按撤销 / 重做、执行选区格式前都先交),和改样式、加粗、删除进同一条栈;连续打字 1 秒内合成一步,选区格式单独一步。改字里按 Ctrl+Z / Ctrl+Y 也转给外层,所以能一路撤回到改字前的加粗(浏览器自己的撤销栈只认这次改字里的输入,撤到头就断,曾经因此撤不回改字前的加粗)。
    - 撤到 / 重做到改字里的一步时,框内原地换回那一步的内容、**不结束改字**,光标放回那一步前 / 后的位置(交回时按字符数记);撤到别的元素的修改时才结束改字。浏览器自己的撤销(`beforeinput` 的 historyUndo / historyRedo)被拦下。
    - 地址输入框关掉后焦点会落到外层页面,外层把焦点放回框里,接着打字仍作用在这段文字上。
  - 删除:只删元素自己那一段;元素独占一行时连同这一行一起删。
  - 链接:`<a>` 改 `href`,其它元素用两次纯插入在内容外包一层 `<a>`。
  - 图片:改 `src`。
- 每次替换后整份重新解析,按「替换前的位置 → 平移后的位置」把编号接回。落在被替换区间里的元素失去编号;改字后新出现的子元素按先序分配新编号。
- 以下几种元素只能「AI 编辑」:
  - 脚本运行时生成的元素:没有编号;
  - 编号被脚本克隆出重复的元素;
  - 源码省略了结束标签的元素:不能改字、不能包链接,但能改样式和删除。
- 进入改字前,框内会比较这个元素当前的内容与源码是否一致。不一致说明被脚本改过,拒绝直接改。
- 撤销 / 重做走应用的撤销、重做快捷键(默认 Ctrl+Z / Ctrl+Shift+Z),Windows 上 Ctrl+Y 也是重做(与程序里的输入框、富文本编辑器一致)。
  - 每一步记下前后两份草稿与编号表,以及框内的正向 / 反向操作:改样式还原成修改前的声明值,改属性还原旧值,包链接对应拆掉那层 `<a>`,删除时框内留着节点、撤销原样插回,改字按当时编号表生成的源码片段换回元素内容。
  - 撤销 / 重做只在框内原地重放,**不重新加载页面**:重新加载会整页闪一下,页面脚本的运行状态也会丢。
  - 同一元素同一属性 1 秒内的连续修改合并成一步,最多 100 步。
- 保存走文件详情原有的草稿通道:Ctrl+S、未保存圆点、磁盘冲突 409 提示,手动保存。

## AI 编辑

把选中元素放进输入框,作为选区引用卡片,复用 `createSelectionContext`。

- 有编号的元素带文件路径、精确行号和元素源码。
- 脚本生成的元素带选择器和运行时的 HTML,并注明源码里没有这段。

### 拖出的选区

编辑模式里在页面任意位置按下拖动(超过 5 像素)画出一块矩形选区,松开后留在页面上,按页面坐标记、跟着滚动;上方只有「AI 编辑」。单击元素、按 Esc 或重新拖一块都会取消它。

- 拖动时页面自己的文字选择与拖放被拦下(`selectstart` / `dragstart`);改字的元素里照常拖选文字。松开后那次 click 只吞掉,不当成选元素。
- 选区里的元素(框内运行时算):完全落在选区里的最外层元素,加上有四分之一以上落在选区里的文字 / 图片元素(标「只有部分在选区里」);标题、段落这类盒子横跨整行的文字元素按文字实际占的范围算。都没有时取包住整个选区的最小元素(标「选区在它里面」)。最多 30 个。
- 按下事件被拦了默认行为,拖出预览框后浏览器不再把移动 / 松开交给框:框开始画选区时通知外层,外层在自己页面上等这次松开,再让框收尾(选区停在最后一次在框里的位置)。手抖拖了几像素、选区宽高不到 6 像素时不算选区,这次单击照常选中元素;按在滚动条上是拖滚动条,不画选区。
- 「AI 编辑」把它作为「选区」引用加进输入框(`htmlRegionContext.js`):走浏览器上下文那条通道(`type: 'browser'`,`kind: 'region'`),标签写「选区」、图标是取景框。正文给模型:文件路径、选区的页面坐标与视口大小,源码里的元素带行号和源码片段,脚本生成的元素带选择器和运行时 HTML。
- 框里报来的选区是不可信输入,外层只留已知字段、截短字符串;它只决定引用里写什么,不改文件。
- 不截图:框是不透明源,页面资源跨源,框内画不出带图片的截图;WorkBuddy 的截图也只用于引用芯片的缩略图,不发给模型。

模型用普通文件工具改文件。Agent 回合结束时,如果改过当前预览的文件,文件详情会自动重新读取(沿用 `nextAutoPreviewRefresh`);也可以右键「刷新」。没有未保存草稿时页面会重新渲染,并恢复滚动位置;有草稿时走原有的磁盘冲突提示。

## 只读与网页端

`/api/files/editable` 只在桌面版托管的 daemon 上可用。所以网页端以及工作区外的文件只能浏览,没有编辑按钮。
