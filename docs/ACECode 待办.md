## 待办清单

### 1. 重做模型设置界面

当前模型设置区域过于简陋，且存在多项设计问题。需要重新梳理信息架构、交互和视觉设计，做成更完整、易用的模型配置体验。

### 2. 完成专家功能，简化新建专家流程

专家功能尚未完成。保留现有“新建专家”按钮，并将其改造成尺寸不变、右侧带下拉箭头的按钮。用户直接点击主按钮时，默认进入对话式创建流程，并自动附加用于创建专家的专用 Skill，由对话引导完成创建；不额外增加一个通用的对话创建入口。点击下拉箭头后显示菜单，其中提供“高级模式”；用户选择高级模式时，才打开原有的新建专家菜单。

### 3. 实现帮助中心与帮助 Agent

设计并实现独立的帮助界面，将软件帮助文档和帮助 Agent 整合在同一入口。用户既能浏览文档，也能通过帮助 Agent 的对话式引导理解软件功能和具体用法。

### 4. 保留聊天中的蜂群模式与专家选择（已完成）

用户在聊天中选择蜂群模式或专家后，发送消息不应清除该选择。当前已选的蜂群模式和专家需要持续保留，直到用户主动更改或取消。

### 6. 变更列表增加树状目录展示（已完成）

为“变更”区域增加可切换的树状目录展示模式。当前扁平逐行的文件列表之外，处于同一目录的变更文件应按照目录层级归类展示，类似 Git 客户端中的文件树，便于理解文件所在位置和结构。

### 7. @ 菜单支持引用会话（已完成）

扩展 Web/Desktop 的 @ 功能，使其可以引用会话。文件与会话在原有下拉菜单内纵向分组展示，共用同一个滚动区域；分组名称随界面语言显示为“文件”与“会话”，或“Files”与“Sessions”。会话行只显示会话标题和工作区名称，不显示更新时间；无工作区时显示“任务”或“Task”。只输入 @ 时默认显示最近 10 个可引用会话，输入首个查询字符后显示所有匹配结果。选中后插入稳定的内联会话标签，发送时由服务端安全解析并加载有容量上限的会话上下文。

### 附加任务：Mac 浏览器浮层局部穿孔（待 Mac 真机验收）

让 macOS 上的 Agent Browser 在与右键菜单、选择气泡等浮层相交时，仅让出相交区域，而不是整块隐藏网页；目标与 Windows 的局部穿孔体验一致。

### 8. 根据子代理状态动态切换专家头像

后续运行时根据子代理状态选择专家头像：`working` 用于执行、编程等工作中，`needs_attention` 用于向用户提问或等待确认，`idle` 用于无操作或等待；对应状态头像缺失时继续回退主头像。本项仅记录后续动态切换，当前已完成的数据字段、编辑与持久化支持不代表已实现运行时自动切换。

### 9. 项目的一键编译与运行流程

当 AI 完成一个项目时，AI 应能将该项目的编译指令和运行指令整理为一个固定的执行流程，并通过 ACECode 提供的内置工具写入这个流程。ACECode 界面提供对应的一键执行按钮；用户要启动项目时可以直接点击按钮，不必再让 AI 临时分析并执行启动命令，从而减少等待时间，尤其方便新手用户。

简单细化：该流程以项目为单位保存，至少包含编译和运行两个步骤；AI 在确认项目可构建、可运行后调用内置工具写入或更新流程，用户随后从固定入口一键执行。

建议：将“一键运行”放在当前项目的常用操作区，例如顶部项目工具栏或工作区标题附近；未配置流程时不展示主按钮，改为提示“由 AI 配置运行流程”。按钮可保留一个下拉入口，用于查看或编辑已保存的编译、运行步骤。

### 10. 让 ACECode 能安全操作和协同自己的会话

参考 Codex 的 app-server、动态工具和 AgentControl 分层，让 ACECode 中的 AI 能在受控范围内创建、读取、等待、发送消息、终止、改名、归档、置顶和分叉会话。先抽取统一的 `SessionControlService`，供 REST、Web/Desktop 和模型工具共同调用；模型工具不得反向调用 ACECode 自己的 HTTP API，而应直接复用 `SessionRegistry`、`SessionStorage`、`AgentLoop`、事件游标和现有置顶状态存储。

用户拥有的普通会话与内部子代理必须保持两套权限边界：普通会话操作遵循当前工作区、用户明确意图和工具权限；子代理通过同一根会话树内的稳定路径、Mailbox、事件驱动等待、消息投递、单独中止以及并发/深度/预算限制进行协作，不得借子代理工具任意控制其他用户会话。首版不向模型开放永久删除、purge 或批量清理能力。

同时控制工具本身带来的上下文开销：建立能力目录并按当前表面、会话权限和用户意图筛选工具；只常驻少量高频查询工具，低频修改、创建和分叉工具按需加载，后续可接入类似 `tool_search` / `deferLoading` 的渐进式暴露机制。会话列表必须分页，读取默认只返回摘要、状态和最近结果，等待只返回事件 cursor 之后的变化，子代理只向父会话送回必要结果或短摘要，避免把完整工具定义、会话历史和中间过程反复塞入模型上下文。

### 11. 修复 Desktop 切换会话时输入框串值与白屏（已知坑）

Web/Desktop 的 `RichComposer` 会跨会话复用同一个 Slate editor。中文输入法仍处于组合输入状态时切换会话，外部草稿同步可能让 Slate 根节点短暂或永久变成空数组，同时遗留指向 `[0,0]` 的选区，进而出现输入内容（例如“啊啊”）跨会话串显、无法输入以及整个界面白屏。

修复时不得通过给编辑器增加会话级 React `key` 来强制重建，因为这会带来明显的会话切换性能开销。应保留 editor 实例，通过会话同步代次隔离旧回声，在组合输入期间延迟外部文档替换，并保证替换过程始终至少保留一个合法 paragraph；同时补充中文组合输入、快速连续切换、空草稿切换和异常回退的回归测试。

### 12. 优化侧边聊天，增加现有界面内的内部聊天

参考 Codex 的侧边聊天机制和交互，改善用户在当前任务中临时提问、探索和补充讨论的体验，但不要为此再增加一个独立、常驻的 Sidebar。优先在现有聊天界面内部提供可展开和关闭的“内部聊天”，让它与主对话保持区分，同时不额外占用一套侧边栏空间。

内部聊天应按需继承当前会话和工作区的必要上下文，避免临时讨论打断或污染主对话。具体的消息归属、上下文范围、是否支持把结论带回主对话，以及 Web/Desktop 的呈现和切换方式，实施前应对照 Codex 的实际机制进一步细化。

### 13. 上下文未达本地上限但后端报溢出时触发紧急恢复

当 ACECode 计算出的上下文用量尚未达到模型上限，但 Provider 或后端仍明确返回上下文过长、请求体过大或 Token 超限等错误时，应将其识别为后端实际限制与本地估算不一致，而不是继续执行普通重试。此时自动触发一次有次数上限的紧急恢复：保留完整的人类可见会话记录、当前用户输入和可恢复检查点，只对 AI 实际发送的历史进行更激进的压缩或按完整逻辑组裁剪，然后重新构造请求并重试当前回合。

紧急恢复不得重复执行已经成功的工具、不得产生重复消息，也不得因连续失败而无限压缩或重试。系统应把触发原因、Provider、模型、本地估算值和后端错误记录到诊断信息，并在界面提示用户正在进行紧急上下文恢复；达到重试上限后必须安全停止，保留原会话并给出手动压缩、继续到新会话或重试等可选恢复入口。429、5xx、超时等普通后端故障必须与明确的上下文溢出错误分开处理。
