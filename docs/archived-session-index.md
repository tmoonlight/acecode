# 已归档会话索引

归档列表(Web 设置 > 已归档、TUI 设置中心的归档页)只读一份「哪些会话归档过」的清单,不再把每个项目目录的会话文件全部打开。实现在 [archived_session_index.hpp](../src/domain/session/archived_session_index.hpp)。

## 为什么要有它

原来的归档列表对每个工作区都把 `projects/<哈希>/` 下的 `.meta.json` 全读一遍,再挑出 `archived=true` 的。归档状态写在每个文件里面,只看文件名和修改时间分不出来,所以没法像普通列表那样只读最新几条。

实测(2026-11-24,本机):一个工作区目录有 5065 个会话、一个归档都没有,冷读一次 23~30 秒,刚读过一次后 0.2~0.3 秒;无工作区会话一路 743 个文件,冷读 3.5 秒。盘是 NVMe SSD,时间耗在逐个打开文件上。页面要等所有工作区的请求都回来才显示,所以最慢的那个目录决定了整页的等待时间。

## 文件与格式

`<数据目录>/archived-sessions.json`,与 `projects/` 同级,用 `update_state_json_at` 的进程锁 + 文件锁(`archived-sessions.json.lock`)做读-改-写。

```json
{
  "version": 1,
  "scanned_projects": { "845dfa38f75a874b": true },
  "no_workspace_scanned": true,
  "sessions": [ { "project": "845dfa38f75a874b", "id": "20261124_230300_ab12", "no_workspace": false } ]
}
```

- `project` 是 `projects/` 下的目录名,`id` 是 meta 文件名去掉 `.meta.json`。只存相对名字,数据目录迁移后照样有效。
- 只认 `<根>/projects/<目录名>/<id>.meta.json` 这一种布局;别的目录不建索引,列表退回整目录扫描(测试里随手建的目录就走这条)。

## 三条规则

1. **登记在落盘之后**:`SessionStorage::write_meta` 每次成功写下 `archived=true` 就登记一次(已在就不写)。所有改归档状态的路径都经过 `write_meta`:网页按钮、批量操作、定时任务自动归档、TUI、opencode 导入。
2. **只增不删,读时剔除**:取消归档、永久删除不碰索引。列表读到某条 meta 已不存在或已不是归档状态,就在文件锁里**再读一次确认**后剔除;文件在但读不出来(正被替换、内容损坏)不剔除,下次再看。所以索引是归档会话的超集。每次写索引时还会顺手删掉项目目录已经不存在的条目和扫描标记(删掉的工作区;Web 单测把会话写进真实数据目录、跑完删掉目录),否则这些条目只有列出那个目录时才会被检查到,会越积越多。
3. **每个目录第一次整读一次**:没标记 `scanned_projects` 的目录第一次列出时整目录扫描,扫到的归档会话与索引现有内容在锁里取并集后再标记。扫描本身不持锁;扫描期间别处归档的会话靠它自己的登记补上(登记要等锁,排在提交前后都不会丢)。无工作区会话一个会话一个目录,整体用 `no_workspace_scanned` 一个标记。

升级后第一次打开归档页,每个目录还会整读一次(慢的那次),之后不再整读。

## 已知限制

- 目录已经标记为已扫描之后,再用不认识索引的旧版本归档的会话不会出现在列表里。删掉 `archived-sessions.json` 即可重建。
- 索引文件损坏、被删或版本号不认识,等同于所有目录都没扫描过,下次列出时自动重建。
- 数据目录迁移期间 state 写入暂停,这段时间归档的会话登记失败只记日志。

## 测试

[archived_session_index_test.cpp](../tests/session/archived_session_index_test.cpp):首次扫描后只打开登记的文件、`write_meta` 归档立即可见、取消归档与删除被剔除、读不出来的不剔除、索引损坏自动重建、非标准布局退回整目录扫描、无工作区一路只在首次调用目录清单。
